- Why inconclusive: the uncapped ceiling (32-33) is already close to the cap (30), so the cap binds the average and cannot separate "the present path limits the game" from "the game is at about 30 for another reason". The falsifier as written only fires above 33, and the average sat at the cap. A discriminating test needs caps of 60 and 75 (property range 24..75) on the same boot type: if FPS stays at 32-33 the present path is not what limits it.
- `kf3: PROF` (MEASURED, cumulative counters, delta between Confirm and the result screen, about 191-196 s, run 1 / run 2): BAR0 writes **1.81 M / 1.89 M traps (about 9.5-9.6 k per second, about 330 per frame at 29 FPS, INFERRED frame count 29 x 191 s = 5.5 k)** with a vCPU handler time of **791 ms / 851 ms in total = 0.44-0.45 us per trap, 0.14-0.15 ms per frame, 0.4 percent of the wall time**; p99 3.6-4.1 us, max 977 us / 2.97 ms for the whole boot. Other threads, per second of the same window: VA manager busy 36.5 / 37.5 ms (3.7 percent), register drainer 0.7 ms, rpc_held 0.7 / 0.2 ms (cumulative max 70 ms), vidmem view reads 12 ms/s, `workers` busy 1355 / 1308 ms per second (1.3 threads busy; INFERRED: these are the host threads that serve guest work, not a vCPU). `kf3: display fps` lines show the capped tick at 29.9 Hz with copies 29.9 and no over-runs.
