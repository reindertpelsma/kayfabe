## Findings and deviations
- **R1 (harness, kayfabe-infra; found, not fixed).** A second payload leg started as root on a box where a rootless leg already ran fails at once with `KF_PAYLOAD_FAIL suite=infrastructure`: `prepare_checkout` runs `git rev-parse HEAD` in the checkout that `chown_tree` gave to `ci`, and git refuses (`fatal: detected dubious ownership`). Evidence `box/workspace/payload_stdout_WR2_infra_fail.log`; `Rootless.as_root` sets `safe.directory` for an approved root stage only, not for the payload itself. Class: CI-CONVENIENCE side effect (`chown_tree`) / kayfabe-infra bug. Workaround used (a test-environment setting, named here): `git config --global --add safe.directory '*'` for root before WR2. The first attempt of WR2 died even earlier for the same reason in my own `run_leg.sh` (`git rev-parse` as root; `payload_stdout_WR2_failed_start.log`, sha empty); the script now uses the literal sha.
- **R2 (config, mine).** `apps_discovery` refuses to start with less than 5 h left on the soft deadline although the stage took 64 min here (`APPS_DISCOVERY_MIN_REMAINING_MS = 5 h`, "rows whose own timeouts sum to 3.75 h per side"): on a 4 h box budget it can never be started by a payload leg without a longer deadline. Design note for the owner, not a defect of the run. Evidence `box/workspace/payload_stdout_WL1.log` (tail).
- **D1.** `apps` was run to its end (it provisions the apps image the discovery stage boots); its 66 rows are a free cross-check, not a goal. D2: `merge_bar` and all Windows stages were not run (see table). D3: the rootless legs ran on a box where WL1 had provisioned as root, so the root provision half and the user half are not separated (audit item 2 stays open).
- Scrubbing: GPU UUIDs (none found), public IPv4 addresses (none), tokens, e-mail-shaped and licence-shaped strings (none) were searched for before commit; the stage logs already carry `<scrubbed>` for serial and cluster identifiers.
