# P1 measurement harness provenance

STATUS: RESEARCH, 2026-10-19.

CODE READ: Steel Nomad ETW/UI/analysis files derive from `claude/steelnomad-gap-20261018` commit `4f37bd12c`; tiny-submit/BPF/progress analysis files derive from `claude/submit-latency-20261018` commit `e97a35ffb`. Both are open repository measurement tools, not closed-binary analysis. The unchanged raw-COM probe uses the same work as the earlier measurement.

CODE READ: P1 adaptations confine guest files to the P1 directory; scheduled tasks and ETW/PresentMon sessions have a P1 name; PresentMon is only waited for using its recorded PID and creation time, with no global process kill. Original host shell harnesses with broad pkill and shared scratch paths are not copied. The host runner and owned observers are described below; their guest runtime validation awaits hardware. These files preserve the original probe and analysis formats.

CODE READ: `host_measure.py` dispatches file-backed PowerShell through the documented host broker, stages only P1 guest scripts, launches the original tiny probe through P1's interactive task, and captures DxgKrnl Base+Profiler plus timed PresentMon. `sn_analyze.py` now exports its actual graphics-test FILETIME boundaries; `sn_ddi.py` uses those same boundaries and reports unmatched/mismatched profiler records and calls/frame. Runtime validation remains pending hardware availability.

CODE READ: `trace_probe.py` starts and stops only its own BPF/fence observers, validates the explicit QEMU PID against its immutable executable and P1 run directory, resolves public Rust symbols, and associates latch-scoped eventfd writes with the actual fd. No IRQ/irqfd number is assumed. The inherited `hops.py`, `align.py` and `fence_vs.py` retain old grouping heuristics: their default 300 us clustering / 600–1500 us window must NOT be used to claim a mirror result, because an improved path may be faster than either cutoff. Raw fence-value/iteration association and exclusion counts are required; unresolved grouping means no GPU-leg claim.

CODE READ: broker source for the meter comes from the read-only `claude/hitch-20261017` branch, built separately; no merge. `broker_content.py gen` observes the public `nb_tick_content_present` symbol externally. Its field offset is compiler-derived from that exact broker header; it distinguishes new content (`commits_since_present > 0`) from repeated display feedback, and preserves compositor presentation time. `analyze` computes all requested gap/lows/count metrics over an explicit common window. Every arm must use the same meter broker and observation settings. Its instrument cost still needs hardware comparison; a synthetic 40/60 ms gap plus repeated-present smoke check passed.

CODE READ: `iteration_hops.py` replaces the inherited clustering for new claims. It joins adjacent exact fence values, chooses the latest-changing candidate at each common value as the completion-cell hypothesis, reports all candidate lags/coverage and exclusions, and applies no period or doorbell-gap selection. Host-wide nvidia IRQs and overlapping marker/IRQ timestamps remain explicit limitations. The actual irqfd is identified from writes inside the public latch function; all eight-byte writes by this exact QEMU process are then counted, including vCPU reassertions. A synthetic 200 us probe retained all 195 post-warmup iterations. Runtime traces remain unmeasured.

CODE READ: diagnostic output is private: request path `p` freezes the event tail into `p.out`; appending bytes to `p.stats` writes one live counter checkpoint per new length into `p.stats.out`. The host rejects missing/incomplete output. `stats_checkpoint` uses the unconditional relay counters and stops performance arms if actionable backstop work increases. `analyze_nsi.py` reports bounded-tail coverage, contention/accounting differences and source/arming/vector/decision counts without treating dataless readiness as a physical IRQ census.
