# P1 measurement harness

CODE READ: these are optional overnight diagnostic tools. They never acquire or break the shared GPU lock themselves. Host commands require the P1 lease marker, whose PID/start time and flock parent are checked. VM startup/shutdown and disk preparation remain in the lane-owned host helpers; read the lane instructions before using them.

MEASURED: source binary41a8beb0 and author mirror0d7ba743 are immutable. The complete source delta against the pinned mirror is limited to12 kf-chan/kf-qemu files; subsequent commits change only tools/evidence. Production builds exclude both measurement features. Results and their limitations are in `traces/perf_parity_20261019/REPORT.md`, `RESULTS.json`, and `W2_EDGE_RESULTS.json`.

CODE READ: use one persistent throwaway disk and the same unchanged cursor6 broker for every configuration, rebooting between configurations. All actual KF3 flags are saved, including inherited production flags. The author's mirror versus diagnostic-ON is a control comparison; pacer/lazy/cache experiments compare to diagnostic-ON, changing one variable. Headline fps is broker **new-content** fps over the same guest graphics window; UI benchmark fps, steady guest ETW fps, repeated presents, content gaps and guest ISR entry counts remain separate fields.

1. Before QEMU realize, run `boot_irqfd.py` on the selected immutable binary. Wait for its READY file, start the one owned VM, then create its STOP file. The public C ABI vector getter supplies the actual eventfd; no hard-coded descriptor or missing-observation fallback is accepted.
2. Run `host_measure.py --root /data/codex-P1 stage` and its `ui launch` command. Run `trace_probe.py` with the exact binary, active QPID, the boot observer's `--irqfd-map`, and `--fence`. Its exact-fence-value joins produce the per-boot clock map used for broker measurements. Heavy host-path tracing and pure performance captures run separately.
3. Run `run_series.py --root /data/codex-P1 --clock-map <per-boot-map> --prefix <unique-arm> --runs 3 --first-home` only when the UI is on its home page. Subsequent runs use the results page. Extend overlapping primary-fps arms to five captures with `--start 4 --runs 2`, without `--first-home`. The fixed overnight deadline prevents late new captures.

CODE READ: the serial runner checks cumulative guest TDR/153/application failures and new journal Xids after each run. Diagnostic-on captures request unconditional relay counters before/after the capture-plus-decode interval; any increase in backstop_found_work stops the sequence for missing-event investigation. Counter request acknowledgements, clock identity, BPF losses and descriptor/process identity fail closed. Nothing changes a product timeout or adds a PUT poll.

CODE READ: `KF3_DIAG_NSI_TRACE=1` and a lane-owned `KF3_DIAG_NSI_TRACE_DUMP` enable a bounded nonblocking source/vector/arming tail. Appending a byte to the dump path's `.stats` requests a private counter checkpoint; creating the dump path freezes to `.out`. `analyze_nsi.py` reports overwrites, contention and sequence/accounting gaps. A bounded or lossy tail is never a complete whole-run event census. Completion-fd readiness mixes FIFO/HOST and the configured host CE, and physical edges may coalesce. Equal vectors or fence windows do not prove redundancy. A true GPU-fetch timestamp is not supplied by these CPU observations.

MEASURED: raw ETL/CSV/PresentMon archives stay in the lane-owned host directory. Per-run hashes and archive members are recorded before expanded files or guest artifacts are removed. Earlier terminal-marker flakes remain incomplete records with labelled quiet repeats; neither raw results nor outliers are silently replaced. `RESULTS.json` identifies full actual flags and every included probe/capture; `HARDWARE_PROGRESS.md` retains unsuccessful setup and diagnostic attempts.
