# ★ The HARDWARE-BOUNDARY VOCABULARY: which ogkm macro NAMES `tools/derive_hwref.sh` evaluates.
#
# ⊘ Names only — never C. A line is a macro-name PREFIX (every macro whose NAME starts with it) or,
# with a trailing `$`, one exact name. The compiler evaluates the bodies; nothing here parses them.
# `docs/design/V3_HW_BOUNDARY_INVENTORY.md` is the inventory these names come from: every register,
# field and in-memory format kayfabe reads, writes, emulates or decodes, plus the complete field
# group it belongs to (so a family whose layout moved shows up as a differing row, not a missing one).
#
# sections: `swref` = src/common/inc/swref/published/<arch>/<chip>/ + kernel-open/nvidia-uvm/hwref/
#           `class <file>` = src/common/sdk/nvidia/inc/class/<file> (every macro in it, filtered by
#                             the prefixes that follow until the next section; none = all)
#           `struct <file> <type> <member>...` = offsetof/sizeof of a class-header struct
