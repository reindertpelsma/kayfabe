# TSG, ctxshare and channel parity

**STATUS: RESEARCH, 2026-10-26.** PF1, mirror-ON source audit at commit `6564dd5977bbcd6aa947359b55b4aa3d9a5e92f4`. Report/evidence only. No implementation change, host access, GPU operation or capability experiment.

## Findings and limits

**CODE READ, commit `6564dd597`:** the mirror preserves explicit SYNC/ASYNC ctxshare identity and the channel runqueue bit. It does not preserve every allocation flag or control. There are concrete unprivileged gaps: no replay of a timeslice setter received before a twin exists; missing default deferred USER adapters for zcull/PM/preemption buffer binds; discarded schedule skip flags; forced synchronous preemption; unsupported non-engine channel properties; and loss of exact host error statuses in several control adapters. These are distinct from translating guest handles and physical descriptors into owned host objects.

**CODE READ, OGKM 580.159.04 and 595.84:** interleave is not available to a capability-free caller through the ordinary direct control. Both exports have flags `0x10028` and access-right **mask** `0x2`, meaning `RS_ACCESS_NICE`, index 1. That right maps to `CAP_SYS_NICE`, not `CAP_PERFMON`. Do not grant it to kayfabe. The `NON_PRIVILEGED` flag alone is insufficient to classify a control.

**MEASURED, retained run53/run55 probe-window extracts at commit `6564dd597`, [windows_timeslice_order.json](../../traces/tsg_parity_20261018/windows_timeslice_order.json):** each has five timeslice calls after identified host births and five successful 400 µs setter logs. **CODE READ:** this does not repair the early-setter gap. Its frequency in the current performance workloads is unobserved. Actual host ctxsw defaults and post-set modes are also unobserved; the implementation does not force every request to graphics WFI.

**INFERRED:** no audited mismatch is established as the cause of the performance gap or the engine timeout. The requested workload-specific ranking and private benchmark context are in the private PF1 report. Do not infer an effective mode, quantum or workload-wide request distribution from an absent census row.

## Scope and evidence key

Guest GSP traffic is CPU-RM→GSP traffic, while `kf-host` authors userspace→CPU-RM requests. These are different layers. In particular, OGKM reauthors USERD placement and channel privilege before sending its own GSP allocation. A numeric difference between a guest GSP descriptor and a host userspace input is not itself a configuration defect.

The exact capture paths, sizes, pinned revisions and SHA256 values are in [input_hashes.json](../../traces/tsg_parity_20261018/input_hashes.json). For this audit dated 2026-10-26, **MEASURED** means an offline count/value read from the named retained artifact, not a new hardware experiment. **CODE READ** means an implementation/header/export reading. **INFERRED** means a consequence or proposed cause requiring a test. A zero in the census is a zero direct control count within that capture, not proof that a nested deferred bundle or guest-local operation never requested the feature. Parameter values absent from a census are **unobserved**.

Host access classes below:

- **NP0**: `NON_PRIVILEGED`, access mask 0; forwardable by default using owned handles, valid ranges and host RM's limits/statuses. Where eligible intent is discarded, **drop is stricter than necessary**. Fairness quotas are policy, not an additional safety prohibition.
- **NP+NICE**: nominal NON_PRIVILEGED with an extra right requiring capability; unavailable to the required capability-free host client.
- **PRIV / KERNEL / INTERNAL**: not forwardable as the same direct host operation. Delegate required state through an ordinary owned object where an equivalent exists.
- **ALLOC-NP**: allocation class has `RS_FLAGS_ALLOC_NON_PRIVILEGED`, no access rights. Individual fields can still have kernel/admin restrictions or be CPU-RM-authored rather than user inputs. Feature-dependent validation is not a permission guarantee for every bit pattern.

Cheapest tests are proposals only, not performed here:

- **A**: GPU-free adapter/encoder/sequence test with an owned-object model; include success, RM refusal and exact status propagation.
- **B**: a future authorized boot with default-off logging of guest setter parameters, owned host birth/completion, setter result and getter. Key by logical TSG generation, not recycled numeric handle alone.
- **C**: capability-free getter/probe on one's own host objects in a future authorized session. Record UID, effective capabilities, driver, object and exact status. No privileged control, module or driver patch.
- **D**: only after the request and effective mismatch are established, a controlled one-knob A/B with correctness gates and preregistered falsifier. This audit authorizes no such implementation or run.

## Addendum 3: finding versus not a finding

### Early timeslice

**CODE READ, commit `6564dd597`, `chan.rs:3972`, `chanlink.rs:2094`, `submit.rs:5571`: finding.** A setter with no applicable twin has no desired-state cache/replay. Empty passthrough and translated-client inventories return NotOurs; the input-only fallback can ACK it. A nonempty translated inventory with no actual group member can instead return INVALID_STATE. Neither path remembers a quantum for later birth. Existing twins do receive a real host call. Free/reuse also needs generation-aware treatment in a future fix.

**MEASURED, bounded Windows extracts at commit `6564dd597`: [windows_timeslice_order.json](../../traces/tsg_parity_20261018/windows_timeslice_order.json).** “After” means after the identified host BORN line for that logical TSG in that saved extract, not a new hardware timestamp analysis.

**CODE READ, OGKM580 O5:** new group bookkeeping defaults to `128 << 3 = 1024` µs. The 580 common setter's minimum HAL is an inline zero stub in the open generated source; the corresponding 595 common setter removes that check. CPU GSP-client control routes to GSP and updates local bookkeeping after success. SDK says supported hardware values are rounded down, and GET returns the request rather than necessarily the hardware-programmed value. No open source numeric cap such as “unprivileged maximum 1024” was established. Do not invent one or take this common code as proof every u64 is accepted by deployed firmware.

**INFERRED:** a group born after a lost early request can retain nominal 1024 until another real setter, but actual host effective quantum is unobserved. Windows 400 and4000 are supported by the historical observer extracts; Windows 1000/2048 are unobserved in the inspected local artifacts. Linux 2048 is a different retained request. **Not a finding:** that current Windows workloads routinely lose these values, or that all their groups actually run at1024. The current Windows USER birth path holds the allocation reply until native host birth and map insertion (`userrelay.rs`, `chan.rs`); lazy TSG construction alone does not imply a later guest setter is early.

### Effective ctxsw default

**CODE READ, commit `6564dd597`, S1/S3/O7: finding.** No effective-mode readback is recorded by the inspected implementation. GET `0x20801235` is exported NON_PRIVILEGED, mask 0, and can inspect an owned channel. Source input zeros and an unset guest control do not establish the firmware-selected effective mode. The L_CUDA_SS log demonstrates a real compute-CILP setter path, with graphics ignored by flags=1; it is not a WFI default probe.

**Not a finding:** an established host-default/guest-request mismatch, a GFXP→WFI rewrite, or an established CTA/CILP default. Each remains unobserved without a getter on the actual deployed driver and actual channel. No privileged profiler is needed for the proposed getter.

### Interleave and uid1000

**CODE READ, OGKM580/595 O6: finding.** `serverControl_InitCookie` copies `exportedEntry->accessRight` directly into limb0 of `rightsRequired`; it is a **mask**, not an index. `rs_access.h` defines NICE=1, DEBUG=2, PERFMON=3; mask 2 means NICE. NICE metadata permits privileged callers and otherwise runs an uncached access callback, rather than automatically granting it to the object owner. `client_resource.c` reaches `osCheckAccess(NICE)`; Linux maps NICE to `capable(CAP_SYS_NICE)`. PERFMON checks `CAP_PERFMON` (or admin on older kernels); admin is `NV_IS_SUSER()`→`CAP_SYS_ADMIN`.

**CODE READ prediction, not a runtime uid1000 test:** with the default enabled resource-access checks, direct TSG and channel interleave sets by uid1000 with zero effective capabilities fail `NV_ERR_INSUFFICIENT_PERMISSIONS` before LOW/MEDIUM/HIGH reaches the setter. Root with those capabilities absent has no admin exception either. `CAP_PERFMON` alone is insufficient. If resource access is disabled, export flag 0x20 activates privileged/admin admission instead. No cap-free LOW-only exception was located. The ordinary host group constructor selects MEDIUM without giving users authority to change it. This answers the mask/capability question, not the unperformed runtime probe. Retain the required unprivileged process model.
