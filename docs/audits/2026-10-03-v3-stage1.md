**Method.**
- Five read-only area passes, one per area. Each cited `path:line` for every finding and marked
  anything not read in source UNVERIFIED.
- Merged here. Where two areas found the same thing, the entry lists both, keeps the higher
  severity and says where they disagreed.
- Citations for every blocker and major were spot-read again at `12a526df` while writing this
  document. One was corrected: area §2.1 cited gate A at `ci.yml:1138-1145`; the gate is at

- What ran: area §2.1 ran the four lexical gates over a `git archive` export and compiled synthetic
  probe crates in a scratchpad workspace outside the repo (2026-10-03); area §2.7 regenerated
  `kf_walk.ptx` with NVRTC 12.2 (2026-10-03). No box, no GPU, no guest.
- Wording is defensive: each entry describes a property, the gap and the check that enforces it.

**Severity.**
- **blocker:** a property the security model states does not hold, or rests on an untested
  assumption, and the gap is reachable from the guest. Closed or owner-accepted before any public
  binary (plan §0).
- **major:** a guest-reachable weakness with bounded reach; or a soundness, gate, ledger or test gap
  that leaves a model property unenforced even where no guest path reaches it today (the owner's
  rule that the unsafe side must hold even when safe code is wrong).
- **minor:** latent (no current path reaches it), or bounded impact.
- **info:** recorded so the next reader does not rediscover it.

**Who can trigger it.** Every blocker and major names who can compose the triggering request: guest
userspace (through guest RM or its own GPU work), guest root, the host, or nobody today (a code
author or a process gap). nvkvm-pv over-rated two criticals by asking only whether a handler was
reachable (nvkvm-pv `docs/audit/README.md`, correction of 2026-08-29); this column is the fix.

**IDs.** `S1-xx`, grouped by area with gaps: §2.1 → 01-16, §2.5 → 20-34, §2.6 → 40-50,
§2.7 → 60-72, §2.10 → 80-91.

## 2. Findings by area

### 2.1 No host-process pointers in safe code

Area summary. The kf3 link graph at `12a526df` is kf-qemu plus 15 kf-* crates plus `libc`
0.2.189, and nothing else (`cargo tree -p kf-qemu --offline -e normal,build`). All four lexical
gates are green on that tree: the unsafe-surface gate and the host-pointer gate report 0
offenders, and the ratchet matches kf-linux-raw 75, kf-cuda 75, kf-qemu 44. What holds:
`scripts/ci/dependencies.py` keeps every `kayfabe-*` crate (including the gate-exempt
`kayfabe-doorbell`) out of kf3; the graph has no `build.rs`, `include!`, `#[path]`, proc-macro or
`global_asm!`, and its one `asm!` (`crates/kf-linux-raw/src/mapping_unsafe.rs:901`) is in an
`*_unsafe.rs` file; `HostSpan` is minted bounds-checked (`mapping_unsafe.rs:946-960`), opened only by
`unsafe as_ptr` (`:980`) and only at the FFI (`crates/kf-qemu/src/ffi_unsafe.rs:361-366`,
`:408-411`), and the C side re-checks the length (`qemu/hw/misc/kf3/kf3.c:178`); RM indirect
pointers exist only inside `chardev_unsafe.rs` and are scrubbed after each syscall; `RawRegion`
accessors bound with `checked_add` (`crates/kf-qemu/src/raw_unsafe.rs:37-41`); Clippy's
`undocumented_unsafe_blocks = deny` runs in CI (`scripts/ci/clippy.sh`). What does not hold
follows. None of it was found to be guest-reachable today.

#### S1-01 · major · The lexical unsafe gates can all be passed at once by rustfmt-clean code
- **Where:** `.github/workflows/ci.yml:1462-1473` (gate A, forbid inheritance), `:676-682` (gate C's
  comment filter), `:671-675` (the comment saying the weakened case "is not expressible in Rust").
- **Who can trigger:** a code author; this is CI integrity, not a guest path.
- **Found:** Gate A runs two independent line greps, `^\[lints\]` and `^workspace = true`. An empty
  `[lints]` table plus a `[dependencies.x] workspace = true` row satisfies both, and Cargo then
  applies no workspace lints, so `forbid` is not inherited. Gate C drops every line whose first
  non-blank character is `//`, `/*` or `*`; `*` is also the dereference operator, and rustfmt can
  start a line with `*unsafe { … }` when a `let` wraps. The comment at `:671-675` is therefore
  wrong. Probe (2026-10-03, scratchpad workspace outside the repo, at `7c9234d2`): a crate with both
  shapes passed gates A, B and C, the host-pointer gate and the ratchet, and built with rc=0; the
  control (`[lints] workspace = true`) failed with "usage of an `unsafe` block". The tree itself is
  clean today. The plan's §2.1 relies on these gates being unbypassable.
- **Check:** (a) rewrite gate A with `tomllib` (as `dependencies.py` already does) and require
  `manifest['lints'] == {'workspace': True}` exactly for every member outside `AUDITED`; (b) add a
  semantic gate: `cargo rustc -p <crate> --lib -- -F unsafe_code` (or clippy with `-F unsafe_code`)
  for every non-`AUDITED` member, so the compiler forbids unsafe whatever the manifest says;
  (c) strip real comment syntax with a small lexer instead of dropping lines that start with `*`;
  (d) known-positive fixtures (S1-12).
- **Status:** open.

#### S1-02 · major · The host-pointer gate sees only pointer type names
- **Where:** `.github/workflows/ci.yml:734-751` (pattern `\*mut |\*const |NonNull|transmute`);
  existing uses of the blind shapes: `crates/kf-util/src/lock.rs:880`, `:923`, `:1348`;
  `crates/kf-util/src/trapwitness.rs:398`.
- **Who can trigger:** a code author.
- **Found:** Safe Rust can create raw pointers and turn them into integers without naming `*mut`,
  `*const` or `NonNull`: `&raw const`/`&raw mut`, `core::ptr::from_ref`/`from_mut`/`null`/
  `dangling`/`without_provenance`, `.as_ptr()`/`.as_mut_ptr()`, `Box::into_raw`, `Arc::into_raw`,
  `CString::into_raw`, `p as usize`, `.addr()`, `.expose_provenance()`. A 2026-10-03 scratchpad
  probe compiled six such shapes under `#![forbid(unsafe_code)]` and the gate flagged none (two of
  them, `* const` and `*const(…)`, are closed by `cargo fmt --check` except inside `macro_rules!`).
  kf-util already turns `&'static str` and `Location` addresses into `usize` keys; that use is benign
  (never dereferenced or printed) but shows the gate cannot see "a `u64` that is really a pointer".
  The gate's own comment (`:715-717`) admits the `usize` case is out of reach; nothing else covers
  it.
- **Check:** workspace `clippy.toml` `disallowed-methods` (the functions above) and
  `disallowed-types` (`core::ptr::NonNull`), allowed only inside `*_unsafe.rs`; Clippy resolves
  types, so inference cannot hide a call. Add `&raw (const|mut)` to the lexical pattern. Re-key
  kf-util's identity maps by an index or token. A fixture file with every shape, and a test that the
  gate reports every line of it.
- **Status:** open.

#### S1-03 · major · The console frame's host address crosses safe code as a `usize`; the C side gets no length
- **Where:** `crates/kf-cuda/src/display.rs:44-53` (`pub fn addr(&self) -> usize`),
  `crates/kf-cuda/src/driver_unsafe.rs:1345-1355` (`PinnedBuf { ptr: usize }`),
  `crates/kf-qemu/src/display.rs:421-437` (`pub struct FrameView { pub addr: usize, … }`),
  `:1672-1681` (publish), `crates/kf-qemu/src/ffi_unsafe.rs:513` (`data: f.addr as *mut u8`),
  `qemu/hw/misc/kf3/kf3.h:31-35` (`Kf3Frame` has no length), `qemu/hw/misc/kf3/kf3.c:696-703`;
  the rule: `docs/design/THE_CONSTRAINTS.md:107-112` (§13).
- **Who can trigger:** nobody today. The guest steers the frame geometry, but `w×h ≤ MAX_PIXELS`
  and the frame is sized to the need.
- **Found:** §13 says host addresses cross safe code only as the opaque `HostSpan`. The page-locked
  console frame's address leaves kf-cuda as a public `usize`, travels through kf-qemu's safe display
  worker and lock-free `ConsoleShare` slots, and becomes a pointer again by an integer-to-pointer cast
  in `kf3_display_frame`, checked only for non-null and non-zero. QEMU then reads `stride × height`
  bytes from it. The read is in bounds only because two pieces of safe code agree:
  `compose_finish` refuses `n = w*h*4 > dst.len()` (`crates/kf-cuda/src/display.rs:282-289`), and
  `completed()` publishes the same `(w, h)` with `stride = w*4`
  (`crates/kf-qemu/src/display.rs:1669-1677`); `FRAME_MAX = MAX_PIXELS*4` (`:1499`, `:1730`,
  `:1769-1775`). The C check `f.stride < f.width` (`kf3.c:697`) compares bytes with pixels. Frame
  lifetime is untyped too: the pinned memory belongs to the display CUDA context, which
  `DisplayGpu::drop` destroys (`crates/kf-cuda/src/display.rs:483-491`); it is safe only because
  frames are retired, never dropped, and `kf3.c` closes the console before `kf3_unrealize`
  (`kf3.c:871-875`).
- **Severity note:** §2.1 rated this major (§13 broken as written); §2.6 rated it minor (the bound
  holds by arithmetic today). Major is kept.
- **Check:** mint a `HostSpan` (or an opaque kf-cuda `PinnedSpan { base, len }`) per frame; carry it
  in `FrameView` instead of `addr: usize`; add `uint64_t len` to `Kf3Frame` (bump `KF3_ABI`); refuse
  in `kf3_display_frame` unless `stride >= width * bpp(format)`, `stride * height <= len`, and both
  fit an `int`; mirror the check in `kf3.c`. Unit test: a `FrameView` whose `stride × height`
  exceeds the frame makes `kf3_display_frame` return -1. Remove `Frame::addr()`. Extend the CI gate
  to flag `fn …addr(&self) -> usize` and `addr: usize` fields outside `*_unsafe.rs`.
- **Status:** open.

#### S1-04 · major · kf-cuda's public safe API takes raw device addresses and puts the bound on callers
- **Where:** `crates/kf-cuda/src/driver_unsafe.rs:672-682` (`mem_free`), `:684-718`
  (`memcpy_h2d`/`d2h`), `:720-747` (`launch_raw`, arbitrary parameter bytes), `:792-806`
  (`memcpy_d2d_async`, SAFETY "callers size them"), `:812-822` (`memset_d8`, SAFETY "every caller
  bounds [dst, dst+n)"), `:828-842`; re-exported as `pub use driver_unsafe::Cuda`
  (`crates/kf-cuda/src/lib.rs:33`, `:38`).
- **Who can trigger:** nobody today; every caller is kf-cuda's own `walk.rs` and `display.rs`,
  which bound through `at()` (`display.rs:435-446`) and the store bounds.
- **Found:** `CUdeviceptr` is a public alias for `u64` (`driver_unsafe.rs:41`). Any crate depending
  on kf-cuda (kf-mem, kf-qemu, kf-harness) can call `memset_d8(any_u64, …)`, `memcpy_*`,
  `mem_free(any_u64)` or `launch_raw` with arbitrary bytes from safe code. A safe function whose
  SAFETY comment states a caller precondition is an unsound API, and it breaks the axiom quoted in
  `crates/kf-linux-raw/tests/unsafe_naming.rs:4-6` ("the raw layer must assume safe code is
  bugged"). The soundness argument lives in two safe files that no ledger lists (S1-06). Under
  unified addressing these are host-memory primitives, not only GPU ones (S1-05).
- **Check:** make the raw-address methods `pub(crate) unsafe fn`, or replace them with methods on an
  opaque `DeviceSlice { base, len }` minted only by `mem_alloc_zeroed`/`import_and_map`, whose
  `at(off, len)` re-validates inside `driver_unsafe.rs`. Make `launch_raw` private and expose only
  typed launches over `abi.rs` structs. A trybuild compile-fail row: `cuda.memset_d8(0x1000, 0, 8,
  "x")` from another crate must not compile. A unit test that an out-of-range `DeviceSlice::at` is
  refused.
- **Status:** open.

#### S1-05 · major · Under unified addressing or HMM, kayfabe's in-process CUDA contexts can address the VMM
- ⊘ **Status 2026-10-03: NARROWED by owner ruling §Q.** Host-process addresses reach a GPU only in
  kayfabe's own contexts, and no guest value is ever used as one. HMM is not refused. What remains is
  check (b) below: the GPU-side bounds are host-memory-safety obligations. Above all, nothing yet tests
  that the compose kernel's address function stays within `ComposeLayer::check`.
- **Where:** contexts created in QEMU: `crates/kf-cuda/src/walk.rs:1948-1975`,
  `crates/kf-cuda/src/display.rs:408-430`; compose bounds host-side only:
  `crates/kf-cuda/src/display.rs:122-154` (`ComposeLayer::check`), `:267-273`;
  `cuda/display/kf_scanout.ptx:79-198` (no store bound inside the kernel); walker bound:
  `cuda/walk/kf_walk.cu:409-447`; `docs/design/V3_BUILD.md:214-219` records `pageableMemoryAccess=1`
  in a CUDA test on a bench host.
- **Who can trigger:** guest root, if a GPU-side bound is wrong: it steers compose geometry (pitch,
  block height, offsets, rows, width) and the page tables the walker reads.
- **Found:** libcuda is `dlopen`ed into the QEMU process. With unified addressing, pinned buffers
  are GPU-addressable at their host address (`pinned_device_ptr`, `driver_unsafe.rs:998-1013`). With
  HMM or ATS (`CU_DEVICE_ATTRIBUTE_PAGEABLE_MEMORY_ACCESS = 1`), any VMM virtual address is a valid
  GPU address: guest-RAM mappings, the heap, the BAR windows. An out-of-bounds access by kayfabe's
  own kernels is then a host read or write, not a GPU fault. The walker has in-kernel bounds with a
  known-positive (`-DKF_BREAK_BOUNDS`, `kf_walk.cu:21-29`). The compose kernel relies on
  `ComposeLayer::check` plus `extent`, and nothing tests that this formula matches the PTX's
  block-linear address function. No bring-up code queries or refuses pageable memory access.
  UNVERIFIED: whether HMM is active for kf3's contexts on target hosts, and whether closed libcuda
  accepts a host address as a device pointer for `cuMemcpyHtoD` or `cuMemsetD8`.
- **Check:** (a) at `bring_up_on`, query `PAGEABLE_MEMORY_ACCESS` and
  `PAGEABLE_MEMORY_ACCESS_USES_HOST_PAGE_TABLES`, log them in the identity line, and refuse or require
  an owner override when set; or record every GPU-side bound as a host-safety obligation (model
  R3.5). (b) A proptest that runs a CPU model of `kf_scanout.ptx`'s address function
  (`kf_disp::scanout::bl_offset` for block-linear, `y*pitch + x*4` for pitch) over random layers
  accepted by `ComposeLayer::check` and asserts every byte address is below `src + extent`, with a
  known-positive mutant (`need - 1`) that must fail. (c) An in-kernel clamp in `kf_compose`,
  matching the walker's I2.
- **Status:** open.

#### S1-07 · minor · `RawRegion` is `Copy` with no lifetime; copies outlive `kf3_ram_del`
- **Where:** `crates/kf-qemu/src/raw_unsafe.rs:4-28` (`#[derive(Clone, Copy)]`; the adopt contract
  "until this region is dropped from every structure holding it"), `:10-13`, `:145-147`,
  `:196-198`; `crates/kf-qemu/src/ffi_unsafe.rs:313-342` (`kf3_ram_add`: valid "until
  `kf3_ram_del`"); `crates/kf-qemu/src/mem.rs:58-131` (`RamMap::del` removes only the table entry;
  `block_for`/`at_file_offset` return copies); `crates/kf-qemu/src/chan.rs:250`, `:3184-3193`
  (`UserdView::Ram` keeps a copy for the channel's life); `crates/kf-qemu/src/device.rs:1311-1313`;
  `qemu/hw/misc/kf3/kf3.c:601-608`.
- **Found by:** §2.1 and §2.10 (both minor).
- **Found:** A sysmem USERD view keeps loading and storing `GP_PUT`/`GP_GET` through its copy after
  the block leaves `RamMap`, contrary to the stated contract. Section remaps (PAM, BAR moves),
  reset-time del/add pairs and device exit do not free the RAMBlock, so this is latent. It becomes a
  host use-after-free only if QEMU frees the RAMBlock while a copy is held: a host-initiated memory
  unplug (pc-dimm or virtio-mem `device_del`). Rust threads are not QEMU RCU readers, so `call_rcu`
  reclamation does not wait for them (UNVERIFIED against QEMU 10.2). `BackendFd` copies are
  short-lived lookups and the RM import holds its own file reference; no fd-reuse path was found.
- **Check:** a generation plus an `Arc` keep-alive per block; make `RawRegion` non-`Copy`, or have
  `UserdView::Ram` store `(gpa, generation)` and re-resolve on every access, refusing by name when
  the block is gone; `kf3_ram_del` waits out live leases off the vCPU; or refuse memory hot-unplug
  while kf3 is realized. Unit test: register a block, create a sysmem USERD view, `ram_del`, and the
  next `GP_PUT` load is refused.
- **Status:** open.

#### S1-08 · minor · Eleven safe `pub extern "C" fn` entry points dereference a raw handle through a private helper
- **Where:** `crates/kf-qemu/src/ffi_unsafe.rs:55-59` (`fn dev(h: *mut c_void) -> Option<&Device>`);
  safe entries at `:292`, `:300`, `:309`, `:372`, `:419`, `:427`, `:463`, `:472`, `:529`, `:566`,
  `:578`; `pub mod ffi_unsafe` at `crates/kf-qemu/src/lib.rs:14`.
- **Found:** `kf3_shadow_seal`, `kf3_bar0_write`, `kf3_bar0_read`, `kf3_ram_del`, `kf3_irq_fd`,
  `kf3_bar1_follows_guest`, `kf3_bar1_overlay_done`, `kf3_bar1_usermode_write`,
  `kf3_doorbell_page_offset`, `kf3_doorbell_site` and `kf3_unrealize` are safe functions in a public
  module whose soundness depends on `h` being a live `Box::into_raw` result. Clippy's

  unsafe entry points' `# Safety` sections (for example `:180-182`, `:207-209`) omit the `h`
  precondition. The only caller is trusted C (`kf3.c`).

### 2.7 The GPU page-table walker

Area summary. Read at `12a526df`: `cuda/walk/kf_walk.cu` and the committed `kf_walk.ptx`,

structure and with known-positive tests:
- Termination and depth: the serial walk is literally nested, and the parallel walk is a host launch
  loop bounded by `KF_DIRS`. Cycles and self-references are harmless: `TOO_DEEP` is asserted never to be

**C. What the host does with a malformed or hostile result**
1. `try_collect` (`walk.rs:1320-1374`) clamps `pdb_count` and `run_count` to the capacities and decodes
   with exact-size decoders.
2. `capacity_retry` (`walk.rs:1391-1475`) re-walks at most 4 times for `RUN_CAP`, `PARTIAL` or
   `OVERFLOW`; an abort (`BUDGET`, `FRONTIER`, `PDB_CAP`) or a report-level truncation is passed up.
3. `GpuWalker::poll` (`vasmgr.rs:382-491`) runs `validate`, then `require_diff`, and refuses a TRUNCATED
   report whole; every want in the batch stays armed and its splits fail (S1-61).
4. Per entry (`vasmgr.rs:1286-1444`): a missing or reassigned object or slot is skipped; a moved root is
   re-walked; `OVERFLOW` fails the space; refused bits count as absent-only.
5. `apply_entry` (`apply.rs:306-540`) checks each run: store and guest-RAM bounds (`ledger.rs:78-111`;
   kf-qemu `mem.rs:105-143`, with `checked_add`); whole 4 KiB pages; the CPU window extent
   (`cpuwin.rs:165-171`); VMM-reserved VA overlap; PRIV leaves withheld from user twins; usermode
   (`kf-chip usermode.rs:108-124`) and SKED (`apply.rs:592-600`) leaves classified. Each run gets its own
   verdict; then it acks, and only after that clears.
6. A device fault surfaces through `event_query` as `Err` (`walk.rs:1327-1338`); the context then stays
   in error, so later walks of this VM fail. VM-local only.

**D. Work bound** (computed from source, not run): per expand level at most `min(nin, 131 072)` warps ×
512 words × 8 B (≤ 512 MiB); leaf phase at most 131 072 × 544 words (≤ 557 MiB); after an abort the
following levels still expand stale entries (S1-63). Roughly 1 GiB of loads per refresh, one refresh in
flight, at a rate the guest sets.
