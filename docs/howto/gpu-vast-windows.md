# The Windows stage of the gpu-vast check

**STATUS: LIVE source guidance, updated 2026-11-09.** The middle application policy
requires the matching Worker bundle and prepared media; its rollout is not performed here.

CODE READ (`ci/vast-broker/src/tier.js`, `scripts/ci/vast_payload.py`): the `gpu-vast` check on a pull request to `master` (Worker profile `check`) runs the Linux merge bar and the Windows gate (`scripts/bench/box/windows_gate.sh`) on the same rented box. The Worker sets `KF_MERGE_WINDOWS=1` for this profile and `0` for the owner-dispatched die sweep; no request field changes it. A box from a Worker that sends no value runs the Windows stage.

CODE READ (`scripts/ci/vast_payload.py`, `.github/workflows/gpu-vast.yml`): only one `WINDOWS_GATE_PASS` line for the tested revision, with exit 0, passes the stage. `WINDOWS_GATE_FAIL` fails the check as a guest failure (suite `windows_gate`). `WINDOWS_GATE_RETRY`, a refused precondition, a missing or doubled verdict, or too little time left before the soft deadline all fail the check as well. With Windows apps requested, the gate reserves its own 75 minutes plus the apps' 70; apps alone require 70. The status then reads "GPU gate RETRY: not a verdict; re-run on a fresh box", and the job log names the suite `windows_retry_<class>`. A RETRY is never a pass: re-run the check, which rents a fresh box.

CODE READ (`ci/vast-broker/defaults.json`, `runner.py`, `gpu-vast.yml`): the check's hard limit is 300 minutes (`HARD_RUNTIME_MINUTES`). The runner waits up to 330 minutes, and the job allows 345. The sweep keeps 180 minutes. A run at the $1/h price cap reserves up to 5.02 USD (300 minutes plus one cron minute), so the default $6 day admits one such reservation at a time. See [budget settings](vast-budget-settings.md).

Windows media come from the vendors' public URLs, pinned by sha256 and size in `scripts/bench/windows/win_vm.sh`: the Windows 11 LTSC 2024 evaluation ISO, virtio-win 0.1.302, OpenSSH for Windows and NVIDIA 580.88. The box needs no credential for them.

With the matching 2026-11-09 Worker bundle installed, a middle-tier PR-to-master check requests the Windows application matrix's `mid` profile: ten probes including every one of the eight `small` probes. Linux's 63-app middle list runs before the Windows gate; Windows apps run after it. Push/small keeps today's check. The owner switch `MIDDLE_APPS_ENABLED=false` disables both new requests. The source change itself does not deploy the policy or qualify a combined hardware run. The `small`, `mid` and `full` application profiles need application media with committed checksums. Missing media, missing app results or an unfinished run never pass. When only input or harness faults occur, the stage asks for a retry; a guest failure takes precedence. A successful application stage requires every selected app to pass and the same-box host reference to remain green.

Release software definitions remain unverified until they run on hardware. In particular, the Blender definition requires passing image comparisons for both CUDA and OptiX against native references, and the llama.cpp parity definition requires matching native output from the same executable and model. Missing references cannot pass. These definitions do not enable additional stages in the default check.
