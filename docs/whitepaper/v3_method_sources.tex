\section{Method and reproducible commands}

This edition used source reads, Git ancestry checks, the claims ratchet, publication-gate tests
and XeLaTeX. It ran no Cargo or Clippy command, VM, real-GPU gate, provider operation or remote
host experiment. Every hardware result is carried from the named repository record. The
experimental source index is deliberately separate from the implementation baseline.

\subsection{Reconstruct the source snapshot}

\begin{verbatim}
git fetch origin next master
git worktree add -b codex/whitepaper-v3-20261027 \
  ../kayfabe-paper origin/next
cd ../kayfabe-paper
git rev-parse HEAD
git log --first-parent --oneline origin/master
# The implementation pin must equal the cover, not a later moving ref:
git show 12c4008705f17033a803e56d4d479bf1275cdb94:AGENTS.md
# Experimental code is inspected without changing the baseline:
git show 2196a9ad1:docs/design/ENS11_SPLIT_LATENCY_20261027.md
\end{verbatim}

The worktree command documents how this writing branch was created; it is not a suggestion to
reuse an existing branch name. \code{sources_v3.json} records immutable paths and Git blobs.
It can be checked without building the product:

\begin{verbatim}
python3 - <<'PY'
import json, subprocess
from pathlib import Path
p = Path('docs/whitepaper/sources_v3.json')
for row in json.loads(p.read_text())['sources']:
    ref = row['revision'] + ':' + row['path']
    blob = subprocess.check_output(['git', 'rev-parse', ref], text=True)
    assert blob.strip() == row['blob'], ref
PY
\end{verbatim}

\subsection{Reconstruct the PR inventory}

\begin{verbatim}
gh pr list --state open --limit 200 \
  --json number,title,headRefOid,baseRefName,isDraft,url
# For a specific snapshot head:
git merge-base --is-ancestor <head> \
  12c4008705f17033a803e56d4d479bf1275cdb94
\end{verbatim}

The live query will differ after publication. \code{pr_snapshot_v3.json} preserves the captured
numbers, immutable heads, draft state and the paper's proposed falsifiers. It does not archive
mutable PR bodies or claim that the proposals were tested here. The inventory is a catalogue
of research and integration debt, not a merge recommendation.

\subsection{Build and verify the publication}

\begin{verbatim}
python3 -m unittest discover -s docs/whitepaper -p test_build_v3.py
python3 scripts/ci/debt.py claims
git diff --check
# Commit TeX inputs before producing a publishable PDF.
bash docs/whitepaper/build.sh v3
python3 docs/whitepaper/build_v3.py --check
pdfinfo docs/whitepaper/kayfabe_v3.pdf
pdftotext -layout docs/whitepaper/kayfabe_v3.pdf -
\end{verbatim}

\readcode The v3 target runs XeLaTeX exactly twice with halt-on-error and an input recorder.
The final log must have no TeX error, missing glyph, undefined reference or unresolved citation.
Repository inputs must match committed Git blobs before export. A JSON receipt binds the
input paths and hashes, source commit, compiler version and output digest. A later PDF-only
commit leaves the input blobs unchanged; the receipt remains checkable. This is a local
publication check, not a signed proof of a trusted compiler or host.

\subsection{How a hardware result should be reproduced}

These are repository entry points, listed as a method rather than commands run for this paper.
Use an authorised, exclusively leased machine and record its real configuration first.
The gate and thin-suite commands come from the contributor verification rules.\src{rules}

\begin{verbatim}
bash scripts/bench/v3_gates.sh
KF_DEVICE=kf3 bash scripts/fastguest/fast_suite.sh <tag> 180
bash scripts/bench/cuda_ladder.sh host <tag>
bash scripts/bench/cuda_ladder.sh guest <tag>
bash scripts/bench/perf_compare.sh <rev> \
  --baseline <rev-or-result-dir> --lanes bare,fast --reps 3
\end{verbatim}

\readcode The performance harness documents its own baseline binary, common guest client,
quantisation, noise observations and summary commands. A table must preserve revision, die,
host/guest drivers, nested status, placement, workload settings, flags, sample unit, all failed
runs and the control's spread. A new edition should rerun the chosen cell or retain its dated
status; changing the source pin does not update the hardware receipt.\src{linuxperf}

For the stall case, preregister whether the outcome is application completion, no recovery,
latency or a particular causal stage. Preserve both the default-timeout arm and any longer
observation arm. A missing native GPU clock, incomplete packet association, capped diagnostic
ring or missing guest event must remain a missing observation. Never silently remove it from
the denominator. These requirements follow the instrument limits in the experimental note.
\src{latency}

\section{Glossary of terms and historical names}

\begin{description}[style=nextline,itemsep=0.4em]
\item[ABI] Application binary interface: layouts and calling conventions. Host and guest
  interfaces are selected independently.
\item[BAR0 / BAR1 / BAR2] PCI address windows. In this design BAR0 writes publish register
  demand; the other apertures expose memory without per-access trapping.
\item[CE / GR] Copy engine / graphics-compute engine vocabulary used in source records.
\item[DMA] Direct memory access by the device. DMA progress is not automatically a CPU event.
\item[Doorbell] A notification to inspect already published work; the token selects a route.
\item[GPFIFO / pushbuffer] A ring of command references / the method packets they point to.
\item[GET / PUT] Consumer fetch progress / producer publication boundary. GET is not a general
  execution-completion fence.
\item[IOVA / GPA] Device-visible I/O virtual address / guest physical address. A virtual IOMMU
  can make these differ.
\item[IRQ / MSI / DPC] Interrupt request / message-signalled interrupt / Windows deferred
  interrupt work. A host notification, physical line signal and guest handler are separate events.
\item[MEM\_OP / split] A memory-operation method / a software ordering boundary that waits
  for the required mapping refresh before later work proceeds.
\item[MMU / PTE / PDE / PDB] Memory management unit / page-table entry / page-directory entry /
  page-directory base. A VA-space object can outlive a particular root.
\item[Non-stall interrupt] An asynchronous engine notification; the observer checks its own
  completion value rather than treating the interrupt as a per-packet receipt.
\item[RM / GSP] Resource manager / GPU System Processor. Kayfabe models the guest-facing
  firmware peer and separately uses the real host resource manager.
\item[TSG] Timeslice group: related channel scheduling membership.
\item[USER / USERD] GPU user privilege / channel producer-consumer state memory. USER does
  not describe the host launcher's Unix UID.
\item[UVM] Unified virtual memory. Fault delivery and replay are separate from mirroring
  already present mappings.
\item[WDDM / TDR] Windows Display Driver Model / timeout detection and recovery.
\item[Xid / event 153 / Code 43] Host NVIDIA error record / guest driver event used by the
  campaign / Windows adapter status. These are different observation domains, not synonyms
  for one root cause.
\end{description}

\subsection{Names encountered in historical files}

These labels are decoding aids only. The main argument uses functions and revisions instead
of asking the reader to remember campaign names.

\begin{description}[style=nextline,itemsep=0.4em]
\item[v3 / pre-v3] Current \code{kf-*} product tree / frozen \code{kayfabe-*} predecessor and
  grader dependency closure.\src{architecture}
\item[M / B-prime / baton] Names for relay-handoff alternatives and mixed-workload progress
  experiments. The baseline README cites M's \code{89fc8a222} result. No broad Windows
  comparison of every alternative is asserted here.\src{readme}\src{alternativerelay}
\item[ENS5 / ENS6 / ENS7] Local sparse-admission undo; RM churn and soft slices; framebuffer-scaled
  sparse budgets. Their source index points to an experimental revision, not the baseline.
  \src{admission}\src{rmcost}\src{budget}
\item[ENS8 / ENS10 / ENS11] Consumed-ring wake tests; host-target scope narrowing;
  split-latency/optional-work continuation integration. CPU validation and hardware acceptance
  remain distinct.\src{owed}\src{walknarrow}\src{latency}
\item[T-space] Kayfabe's privileged translated-work address space. A guest USER channel
  must not inherit its whole-memory window.\src{rulings}
\item[Candidate numbers, lane names and short boot labels] Coordination names, not product
  versions or evidence grades. An exact source SHA and run record are required to interpret them.
\item[ogkm] NVIDIA's open GPU kernel modules, used as pinned reference sources. A version tag
  is part of a layout citation; paths and meanings cannot silently move across tags.\src{credits}
\end{description}

\section{What changed from the predecessor}

\readcode The old text describes the earlier multi-process/isolate architecture and records
corrections through its September restamp. It remains an archive. This edition starts from the
single-process v3 product, a GPU-driven page-table diff, the current channel kinds and the
Windows user-ring lifecycle. It does not carry forward old line counts, mutation percentages,
performance floors or claims that a feature has never run.\src{old}\src{architecture}

The audience is broader: each driver-internal concept is introduced before the architecture.
The uncomfortable section separates the older wake defects from the later sparse experiment,
records where a proposed bound was false, and carries a complete open-PR snapshot instead of
implying experiments have landed. The outside-reader questions state setup, requested
observation and the decision it changes. The publication gate records committed inputs and
checks the finished log, because producing a plausible PDF is not evidence that TeX succeeded.

The source pin is explicit and immutable. Experimental sources have a second revision and
reported observations retain their missing raw-trace limitation. This is the successor's
method, not a claim that the old measurements were all wrong or that the new explanation
cannot fail in the same way.
