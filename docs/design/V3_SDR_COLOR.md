# Bounded SDR colour scanout

**STATUS: RESEARCH, 2026-10-06.** Implemented on branch
`codex/sdr-lut-20261006`, opt-in `KF3_DISPLAY_SDR_COLOR=1`; not promoted to master.
The Linux result below is a real GPU transform, not a constructor capability probe.

## Implemented subset

RGB8888 windows, identity FMT, disabled input CSC and TMO, unmirrored DIRECT10
FP16 ILUT (four header entries plus 1025 entries), FP16 blend, OCSC0 matrix,
unmirrored DIRECT10 fixed-point OLUT, and RGB8888 output. Both LUT interpolators
execute on the GPU. Active input CSC, OCSC1, tone mapping, segmented tables,
nonunity OLUT normalization and non-SDR input table entries are refused.
Existing surface planning still refuses other pixel formats. The cursor uses the
existing separate cursor path after the output transform; arbitrary cursor colour
semantics and HDR are outside this experiment.

Method addresses, bit fields, array strides and enum values are generated by
compiling both OGKM class-header versions. Pure tests cover Turing, Ampere, Ada
and GB20x. GB20x's physical LUT addressing is decoded and bounded; its existing
surface scanout backend remains unavailable, so this is not a GB20x graphics claim.

OGKM `nvkms-evo3.c` and `nv-softfloat.h` specify the distinct formats and units:
ILUT offsets are **bytes**, OLUT context-DMA offsets are **256-byte units**;
default ILUT entries are FP16 `i / 1024`, default OLUT entries are `i << 6`.
`GetLUTIndex` shifts 8-bit inputs left two bits. The OCSC0 rounding adjustment is
`1 / 2048`, encoded as 32 in the signed coefficient word. The GPU kernel retains
these values through output, instead of applying a CPU colour reference.

## Bounds and lifetime

The worker resolves each LUT through its owning client/channel incarnation.
The complete 8232-byte span includes the header and repeated endpoint; linear
video memory and aligned entries are required. GB20x physical targets must name
video memory. The CUDA binding separately checks the imported store extent.
No table controls an allocation size: there are 32 input snapshot slots and one
output slot. The colour staging allocation is capped at 3840×2160 pixels.

Each newly armed binding receives a worker-authored token. The GPU copies its
table into an owned snapshot and validates/uses that same snapshot. Refreshes
retain it; UPDATE, disabled binding, channel reallocation/free and new instance
memory invalidate the token. A preserving free retains the already transformed
console frame without reading released tables. No CPU validation/reread race is
introduced. The GPU emits only a four-byte validation verdict to the worker.

Window and core colour updates hold successful notifiers, releases and GETs
behind the real GPU completion signal. A rejected program, invalid FP16 snapshot,
CUDA failure or missing completion stops decoding and drops queued success effects.
A timeout no longer manufactures completion for GPU scanout work. This failure
policy currently requires a new display-device lifetime to resume.
