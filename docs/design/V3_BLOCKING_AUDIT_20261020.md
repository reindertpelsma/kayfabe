# V3 worker blocking audit (2026-10-20)

**STATUS: RESEARCH, 2026-10-20.** Read-only audit of 82830cd5e (`origin/claude/relay-fairness-review-20261020`). Nothing here was run: **every
entry is CODE READ** unless it carries one of two other tags. **QUOTED** = a number or claim that a code comment states as measured (not re-measured here).
**INFERRED** = reasoning from the code or from std/kernel behaviour not in the repo (the nvidia module source is not in `third_party`). No code was changed.

Rule audited (owner, binding): the worker's only blocking point is the one `epoll_wait`; every scheduled task (token serve, relay turn, doorbell
drain, completion dispatch, engine-event dispatch, VA/map actions) does bounded work and returns, registers on epoll, or is spun. Also (CLAUDE.md):
nothing blocks on a vCPU thread or under a lock a vCPU takes.

## 0. Frame

- **Two workers**, both `Device::worker_loop` (`kf-qemu/src/ffi_unsafe.rs:221-229`), sharing `worker_efd`, the completion fd and the engine fds, each in its
  own `Poller`. A stall in one worker leaves one worker for everything; two concurrent stallers freeze all Translated, USER-ring and relay service.
- Other threads: `kf3-drainer` (`drainer_loop`), act thread (`chan.rs:3058`), `kf3-vamgr` (`va_loop`), display, scanline, probe. QEMU main/vCPU threads reach
  Rust only through `bar0_write/read` (atomics + one doorbell store, no Mutex/RwLock) and the C memory listener (`kf3.c:808-857`: `kf3_ram_add/del`,
  `kf3_doorbell_site`; comment: "main loop (or a vCPU in a PCI config write), BQL held").
- Worker entry points: `Plane::worker_pass` (`kf-core/src/plane.rs:545`) -> `owner_of`, `operands_translatable` (x2, `Device::alive`), `run_translated` ->
  `ChanPlane::serve` (`chan.rs:7678`) -> `user_ring_serve` / `relay_serve` / Translated `pump`; `dispatch` (COMPLETIONS_TAG -> `for_each_inflight` ->
  `ring_internal`; doorbell -> `efd.drain`; `on_other` -> `rc_scan`, `relay_refresh_all`, `nsi_engine_edge`; `on_completion` -> `nsi_fifo_edge`; `on_tick` ->
  `nsi_tick`, `user_ring_poll_due`); `RelayLoop::waiting/peek` (`userpump.rs:3146`). Not worker-reachable: acts (act thread), `apply_register` and `dbfast
  service_ready` (drainer), DISABLE/ENABLE acts (act thread; they only `user_ring_wake` the worker).
- Already fine (CODE READ): `Notifier` is `EFD_NONBLOCK` (`kf-linux-raw/src/host_fd_unsafe.rs:485`); `rm.doorbell` is one fenced store (`kf-host/src/lib.rs:880`);
  `memory_access`, `userread` guards and the USER-ring `record` / `pt` / `storage` takes on the worker are `try_*` (a busy lock -> `Failure::Retry`, durable
  `retry` flag); Inbox locks are Vec/HashMap ops; token/bitmap/wake-word CAS loops only retry when another CAS succeeded; `epoll_wait` park is 50 ms or 1 ms
  (owed paced raise); `PollTimeout::Immediate` in look/spin.

## 3. Ranked: what could explain multi-second freezes

Existing evidence to read first: `KF3_PROF=1` line `PROF workers ... max_busy_us ... timeouts_with_work` (`device.rs:3262-3273`; `WorkerStats.busy_ns/max_busy_ns/wait_ns`);
heartbeat `chan[contended=...]` and `views[armed= released= refused= held=]` (`device.rs:1831, 2904-2909`); `USER_STORE_VIEWS ... armed evicted_at_quota rm_refused_*`
(`userstore.rs:51`, shutdown summary); `USER_RING_LOOP SUMMARY` (`busy_looks`, `wake_*`, `backstop_found_work/carried/contended`, `contended`, `event_without_progress`, drain
histogram); `USER_RING_INIT elapsed_us`, `USER_RING_PREPARE elapsed_us`; `act_worst_us/act_total_us`; `PROF vidmem_view_reads n= bytes= ms=` (Translated only, `prof.rs:374`);
kf-mem `HoldStats` (`act_wait_max_ns`, `max_hold_ns`, `va_yield_max_ns`). **Gaps:** there is no lock-wait histogram for `pt`, `record`, `user_rings`, slot, `rows` or `ram.blocks`
(grep found none); the USER-ring snapshot UC copy has no byte/time counter (only the Translated `Mem::read` has `VIEW_READ_*`); `max_busy_ns` only with `KF3_PROF`.

1. **W1/W2 - RM ioctls (map/unmap/open) on the worker.** The only sleeping kernel calls in a task. No timeout, shared host RM API lock with the act thread's RM calls (alloc/free/map) and any
   other RM client on the host, so a slow act ioctl becomes a worker stall of the same length; under Windows D3D11 thrash it is QUOTED as 106 s of system time per worker per 293 s. Frequency
   depends on `user-view-keep` / `VIEWS_MAX`=8. *Falsifier:* `max_busy_us` multi-second with `views[armed - released]` flat and `USER_STORE_VIEWS armed` not growing. *Conversion:* arm off-worker (W1 row).
2. **W6 + W7 - slot lock vs drainer / lost wake.** A worker pump holding the slot for W2+W4 (100s of ms) makes the drainer (blocking `slot.lock()` under the GSP lock) stall: held GSP replies and
   `release_settled` on the VA thread wait, so symptoms look like a whole-device freeze with no worker symptom; and a `try_lock` miss on the worker drops the ring (`contended`), leaving the channel
   idle until the next doorbell/edge (up to the guest's 2 s TDR timer). *Falsifier:* `chan[contended]` stays 0 and `worst_act_us`/drainer-gap are small. *Conversion:* W6/W7 rows.
3. **W3/W4/W5 - guest-sized UC copies (60-200 ms each) under `rows` / `ram.blocks` / slot guards.** Delays VA-thread row commits (hence MMU invalidate completion, the documented hang mechanism)
   and any `RamMap` writer on a BQL/vCPU thread; alone it gives 100s of ms, not seconds, unless BAR1 stalls (GPU reset/TDR: INFERRED, a UC read then waits for the PCIe completion timeout).
   *Falsifier:* `vidmem_view_reads ms` / `max_busy_us` small. *Conversion:* chunk + budget.
4. **W14 - stderr on the worker** with `KF3_MAPLOG` (default in `windows_broker.sh`) printing per engine wake and unconditional `GATE ticket=`; blocks only if the log fs stalls (INFERRED). *Falsifier:* rerun with
   `WIN_DROP="KF3_MAPLOG ..."`, freezes unchanged.
5. **W9 + W8 - `user_rings` held across UC loads; `rc_scan` blocking `pt`.** Each holds a map/lock that the other worker, drainer or act takes blocking, across UC loads; short in the healthy case, long if the GPU stalls.
   *Conversion:* clone-then-iterate; `try_lock` + rescan flag.
6. **W17/W18 - contended USER-ring turns** cost spin (64) + up to 50 ms each (a `record` held across an act RM ioctl); multi-second only if the act holds for that long. Counters: `contended`, `backstop_contended`, `backstop_found_work`.
7. **W11, W13, W15, W16** - low (diagnostic-gated or small).

## 4. Minimal path to the rule

(1) Arm/release CPU views only on the act/VA thread; worker copies from ready views, else `Waiting` + ring on arm completion. (2) Per-turn byte/time budget and chunked copies with
guards dropped between chunks (USER-ring snapshot, Translated pump, `write_authored`). (3) Slot flags (`scheduled/stopped/disabled/dead/guest_idx/tsg`) as atomics so the drainer never takes the slot and
the worker's `try_lock` miss can only come from act `retire`; re-ring on a miss. (4) `try_lock` everywhere on the worker (`rc_scan`, `user_ring_record`, `alive`, `relay_serve`, `hw_words`) with a durable
retry flag + `worker_efd.signal()` from whoever releases (act records, `pt`). (5) No eprintln on per-event worker paths (counters + first-N). (6) Add the missing counters: per-call UC copy ns/bytes in
`userstore`, `try_lock` miss counters for `pt/record/storage/user_rings`, and an always-on `max_turn_ns` per `serve`.
