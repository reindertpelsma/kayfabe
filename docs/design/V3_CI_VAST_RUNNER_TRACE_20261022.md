# GPU tripwire to GitHub build provenance

[CODE READ: .github/workflows/gpu-vast.yml, ci/vast-broker/runner.py] Round 3 supersedes the inline client, request-only GitHub token, cross-run cached PASS and PR-controlled workflow assumptions in the earlier design. The required check is a fallible GPU tripwire. Vast supplies no trusted executable or build input. The final release build originates on GitHub.

| Hop | Authority and public trace | Limit |

Actions records run ID, attempt, base revision and PR head. | GitHub and protected base code are trusted. Fork PRs refuse before contacting the Worker. No PR checkout, cache or artifact input exists in this job. |
| OIDC → admission | CODE READ: Worker checks GitHub signature/audience, numeric identity, exact master `workflow_ref`, run/attempt, base `workflow_sha`, API run membership and current PR head; owner approval remains required. | Public API rate limits refuse service. [CODE READ: runner.py] The runner generates 32 random bytes before its first request. `/rent` accepts exactly runner_nonce, tested_sha and pr_number; the Worker independently cross-checks the target. Final status echoes nonce/SHA and the rolling log hash. Define H0 as 32 zero bytes and Hn = SHA256(Hprev || uint32be(length(chunk)) || chunk). A chunk is the exact UTF-8 byte sequence of each strictly decoded JSON `chunks` string, in cursor order, before runner scrubbing/redaction; no Unicode normalization occurs. This hashes received log values and chunk boundaries, not JSON envelope spelling, HTTP framing or the box's original output. Page hashes and final hash must match the runner's recomputation. Cursor pages may advance beyond a stale pending snapshot, but final cursor/hash must agree. Another run's cached PASS cannot satisfy a fresh nonce, so same-SHA requests refuse within existing budget/gap policy rather than inherit a verdict.

[CODE READ: runner.py] Public display independently removes whole ESC/C1 CSI/OSC/DCS sequences, CR, other C0/C1, DEL, bidi and zero-width characters. The allow-list is printable ASCII, TAB, LF and precomposed Latin U+00C0–U+00FF excluding multiplication/division signs. It redacts known endpoint/token values and opaque token shapes, neutralizes workflow delimiters and prefixes every line `[untrusted]`. Each print has a fresh random stop-commands token. Limits are 1000 bytes/line, 200 lines and about 65 KiB total including live/final framing; the summary has a separate 64 KiB text cap and a fence longer than any retained backtick run. Runner-generated dropped-byte markers identify omitted content. A separate displayed-log digest covers the exact bounded summary excerpt. Public observers can recompute that display digest; redacted/omitted bytes prevent reconstructing the full received-log chain from the public excerpt alone.

[CODE READ: gpu-vast.yml] The Worker job has only `id-token: write`, step-scoped endpoint/path secrets, a fixed no-profile/no-rc shell, `env -i`, Python `-I`, job/step deadlines and per-PR-head concurrency. It sends no GitHub job token to the Worker. Status writers have only `statuses: write` and never receive endpoint secrets. A container is not added: this job executes only protected BASE code on a fresh GitHub-hosted VM, and executes no Worker bytes; another image would add an input to audit without removing GitHub/owner trust. See GitHub's [pull_request_target security guidance](https://docs.github.com/en/actions/reference/security/securely-using-pull_request_target) and [artifact-attestation documentation](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations).

[CODE READ: release_gate.py, release-build.yml] Public verification follows commit → Actions log/base manifest → run-bound structured summary → `gpu-vast` commit status → release workflow SHA → GitHub provenance subject digest. A future binary recipient must compare that digest to the binary they obtain and verify its GitHub attestation. No imported Vast/dev-box binary can satisfy this workflow's build path. Trust-on-owner remains for base changes, deployed Worker code/hash assertion, provider observations and administrator bypasses. GitHub provenance authenticates where the final binary was built; it does not certify a truthful Vast test. The existing KVM payload, hosted OIDC, Cloudflare billed CPU, login-to-MANUAL hook and price/day-cap questions remain open; renting stays disabled.
