## 2. Method

1. **ogkm 595.84 control tables.** I parsed every `__nvoc_exported_method_def_*` table in `src/nvidia/generated/g_*_nvoc.c` (1341 control ids) for `methodId` and `flags`, and read the privilege logic: `rmapi/control.c:673-705` (PRIVILEGED flag 0x4 needs `RS_PRIV_LEVEL_USER_ROOT`; a control with neither NON_PRIVILEGED 0x8, PRIVILEGED 0x4 nor INTERNAL 0x80 is KERNEL_PRIVILEGED and refused to every usermode client), `control.c:797` (INTERNAL 0x80 needs `bInternal`, else `NV_ERR_NOT_SUPPORTED`), `rmapi/alloc_free.c:620-690` (object alloc privilege) and `rmapi/resource_list.h` (per-class alloc flags), and `interface/deprecated/rmapi_gss_legacy_control.c:56-127` with `rmapi_deprecated.h:41-43` (GSS-legacy: bit 15 set is NON_PRIVILEGED, bits 15:14 both set is root-only, and the command is forwarded to the GSP unchanged).
2. **Host.** `ssh root@172.22.1.20 modinfo nvidia`, `/proc/driver/nvidia/version`: [M] NVIDIA UNIX **Open** Kernel Module 595.91.07 (GSP firmware `gsp_ga10x.bin`/`gsp_tu10x.bin` 595.91.07). The DKMS tree (`/usr/src/nvidia-595.91.07`, read-only listing) has only `kernel-open`-style sources plus `nvidia/nv-kernel.o_binary`: the RM core (control tables, GSP RPC) is a prebuilt object, so **a patched RM core is only possible by building the GitHub open-gpu-kernel-modules tree**, not by patching the packaged DKMS sources [M]. Consequences are in s6. I did not look inside `nv-kernel.o_binary` (provenance rule: no closed-binary reading); Q2 answers about 595.91.07 therefore rest on the 595.84 sources and are [I] for the exact host binary.
3. **Captures.** The five Windows 580.88 observer captures on the AD104 (`vfio-dvi-20261008/boot1..3`, `vfio-gl-20261011/boot1..2`, HOST ONLY, abbreviated CAP5 below) were parsed read-only on the host with small scripts (`nice`; framing: 32 B observer header, 16 B queue element header, 32 B RPC header, then `rpc_gsp_rm_control_v03_00` = hClient, hObject, cmd, status, paramsSize, flags..., params at +40 [R: g_rpc-structures.h]); request/reply paired FIFO per (client, object, cmd, size). They produced the "[M: CAP5]" statements (reply bodies, request==reply, one-request-two-replies, class list). The scripts were removed from the host afterwards; no capture bytes beyond non-board values are copied here (no EDID, serial or UUID).
4. **Kayfabe evidence.** `crates/kf-abi/src/hostabi.rs` (HOST_CONTROLS, what kayfabe asks the host), `kf-rm/src/hostfacts.rs` PROVENANCE (which facts are `HostControl`, with the NON_PRIVILEGED notes), `kf-abi/src/gssreplay.rs`, `cudartinit.rs`, `capability.rs`, `docs/design/V3_GSS_NATIVE.md` s3, the inventory's own cells. No probe was run, so "the host answers X" is [M] only where kayfabe already uses the control at realize (5 rows) or where bare-metal userspace measurements are on record; otherwise it is [R] from the control flags and [I] for the exact 595.91.07 binary.
5. **Q3/Q4 vocabulary.** Q3 methods: (a) *same unprivileged ioctl* run per die (root not needed); (b) *root RM client* (stock driver, no module; passes the PRIVILEGED check); (c) *patched full-source open module* that issues a KERNEL_PRIVILEGED/INTERNAL control or a raw GSP_RM_CONTROL RPC below the control table (the V3_CONSTANT_STRATEGY s4.1 spike); (d) root `mmap` of the BAR0 resource for register pages. Method counts over all 140 rows (Q3 column): unprivileged ioctl 52, N/A 33, patched module 27, root client 23, NO 5.

## 3. Things this check measured that the inventory and kayfabe do not say

All [M: CAP5, AD104, Windows 580.88] unless stated. These are the highest-value results; each is a falsifier-ready fact.

1. **Connector table is monitor-independent.** `0x73011d`: the first four (valid) entries are byte-identical in all five captures, DVI and HDMI sessions alike (version 0x40, platform 0, entries {0x46,0x6000,0,0} {0x46,0x1800,1,0} {0x46,0x600,2,0} {0x61,0x100,3,0}). The inventory's "payloads differ between sessions" is explained by entries 4..15, which are **uninitialised memory** (stack/kernel-pointer-like words). The same union matches the `0x73010x` masks by value: `GET_SUPPORTED` 0x7f00 and `GET_HOTPLUG_CONFIG` 0x7f00 equal the OR of the four connector masks [I: that they are computed that way].
2. **GMMU fault-buffer sizes are wrong on AD104.** `0x20800a59` returns replayable 0x54000, non-replayable 0x220c20 (shadow sizes 0); kayfabe serves 0x31000 and 0x120c20 (`authored.rs` GMMU_STATIC). ogkm says the value is a silicon reset default (kern_gmmu_tu102.c:548-566): per die. Not display related; a live per-die constant.
3. **5070 caps differ.** `0x50700709` capsTbl is 0x24 (BUG_381003_MULTIWAY_AFR_WAR | DEEP_COLOR_SUPPORT); kayfabe serves an empty table.
4. **`0x20809064` is request-dependent.** The Windows request {0,3,1,...} gets a 3-entry listing, while the `cudartinit` row was captured for the cudart request {0,1,8}/{0,2,...}: replaying the one captured row (86 times in run 641) is wrong for this request.
5. **Many "stub" answers are exactly what hardware does.** Reply equals request in every call for `0x20800a3a`, `0x20800a9a`, `0x20800afe`, `0x20800aff`, `0x20801110`, `0x20801220`, `0x2080205b`, `0x20802a0f`, `0x20802a12`, `0x2080a088`, `0x20808524`, `0x2080220d`, `0x20801111` (565 calls), `0x20801211` (282), `0x20801208` (159). These are echoes of the guest's own request, i.e. tier 1 by definition.
6. **Derivation found:** `0x20800aaf` ENABLED_SEC2_CLASSES = membership of {0xB6B9, 0x95A1, 0xCBA2} in the class list (the AD104 class list has 0xb6b9 and 0x95a1 and no 0xcba2; reply {1,1,0}). `0x20800a2e` ROP info has the same struct as the public `GR_GET_ROP_INFO` and count == unit*factor. `0x2080121f` poolSize == maxSlots*slotStride (4*0xf96000 = 0x3e58000). FECS record size 128 and CE fault method buffer 0x5000 (141 calls) match kayfabe's authored values; `0x73011a` totals are exactly CEA-861 for the two captured modes (1920x1080 -> 2200x1125, 1280x720 -> 1650x750).
7. **State dependence measured** (one request, two replies): `0x73011a` (follows the armed mode: 1080p vs 720p), `0x73028b` OR_GET_INFO (index -1 before `DFP_ASSIGN_SOR`, assigned index after), `0x731152` (assignment state), `0x20801823` index 0x2d (PCIe gen word 0x333000 vs 0x303000: the link retrains), `0x20800a38` (follows the last SET), `0x20809004` (118 distinct replies in 640 calls: telemetry).
8. **Closed-binary basis replaced.** `0x2081010d` "paramSize 0" was quoted from a retail export row; the captures show request and reply of 0 bytes in 5/5 calls [M], so the claim no longer needs that source.
