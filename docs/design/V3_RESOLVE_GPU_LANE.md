## What Resolve 21.2 free is (MEASURED on image A, 2026-11-16, PC, kf3)

- Version `21.2.0.6` (`Resolve.exe` file version). External scripting and the Python API are not available: the free edition lost scripting in 21.1 (Puget Systems and the 21.1 notes; INFERRED from those sources, the console was not probed). The driver therefore uses the UI only.
- The UI is visible to UI Automation (window tree, page buttons with `button<Page>Panel` AutomationIds, the Deliver controls: ComboBox with ValuePattern, Edit, Buttons `Add to Render Queue`, `Render All`, `Stop`), but menus and file dialogs are drawn without UIA children; those are driven by measured coordinates on the fixed 1920x1080 guest (`File > Import > Timeline` is Ctrl+Shift+I, then the Win32 file dialog and the `Load XML` dialog). A process must call `SetProcessDPIAware` or its screenshots and clicks are scaled.
- Deliver page: formats include MP4, QuickTime, PNG, TIFF-less list (IMF, JPEG, JPEG 2000, MJ2, MKV, MXF, PNG); QuickTime codecs include Apple ProRes, Avid DNxHR, H.264, H.265. **The Encoder control offers only `Auto` and `Native`: no NVIDIA encoder in the free edition** (Studio-only, as Puget and Blackmagic document), although Resolve's own log says `NVENC encodes H264/HEVC/AV1` and `Nvidia GPU (0) is initialised as decoding and encoding device`.
- Resolve's log names its device: `Selected compute API: CUDA`, `Detected 1 GPUs`, `Initializing CUDA board manager`, `Initialized MainPlayer OpenGL I/O on CUDA device 'NVIDIA GeForce RTX 4070'`; `GPUDetect` prints `NVML Error Unknown Error (999): Querying device current PCI link width`, the GPU name as `"NVIDIA "` (empty) and VRAM `3.6 GiB` (the 4096 MiB guest framebuffer).
- A first render of a UHD 14 s H.264 timeline ran at about 2 fps overall; the physical GPU (host `nvidia-smi`) sat at 95 to 98 percent while it ran; the guest WDDM counters of the Resolve process showed video decode up to 98.7 percent, copy up to 22 percent, 3D 0, and no compute engine at all, and the process held 3.0 to 3.4 GiB of dedicated GPU memory. Guest `nvidia-smi` printed `[N/A]` for every utilisation column while `memory.used` was readable (traces README).
- A software H.265 render of the same UHD timeline estimated over an hour in the nested guest; cancelling it hung the Resolve UI (the process had to be killed). The H.265 deliverable is therefore 720p and last.

## The row

`propimage_check.py --apps resolve` (the `propimage_apps` stage passes nothing new): host fetches media and pushes it with the timeline; the guest script creates a project, imports the timeline, grades two clips (three serial nodes: contrast/saturation/boost, temperature/highlights, blur), opens Deliver and renders H.264 MP4, Avid DNxHR MOV, Apple ProRes MOV, PNG sequence, H.265 MP4 (720p). `--resolve-launch-only` restores the old row. Evidence kind FILE (`propimage_apps.EXPECTED_KIND`).

Grading (`resolve_gpu.grade`): PASS needs every render verified from the pulled bytes (codec, size, frame count, duration, decoded middle frame not flat, sha256; PNG sequences: 96 files, first/middle/last frames decoded and different), the guest per-engine counters of the Resolve process busy in the render window (`GUEST_NEED`), the physical GPU busy in the same window on the host (`HOST_NEED`: the guest scheduler does not show CUDA compute), Resolve's log showing CUDA and an NVIDIA device and no "CPU only", and, only where the Encoder control accepted `NVIDIA`, encoder activity. A sampler with no samples or only `N/A` fails with that reason. The shared helper of the image-B lane (`scripts/bench/windows/gpu_assert.py`, branch `claude/imageb-apps-20261116`) asserts through guest `nvidia-smi` utilisation columns, which this guest reports as `[N/A]`: it would fail every row on kf3 for that reason alone. `gpu_use_assert.py` takes the same shape of verdict (`ok`, `reasons`, `summary`) and adds the WDDM engine counters and a host sampler; the two are to be merged by keeping the engine counters and the `[N/A]` rule.

Not covered, by name: optical-flow retime (a project setting not driven; the FCPXML retimes use Resolve's default retime process), Fusion compositions and Resolve FX (not driven), the Preferences "Memory and GPU" page (the Preferences window did not open from the driver; Resolve's log is the source of its GPU configuration), and Resolve's `Help > Create Diagnostics Log`. PugetBench for DaVinci Resolve: free for personal use, $750 commercial, no redistribution terms stated on its pages; it needs scripting, which free Resolve dropped in 21.1 (Puget: the free edition is supported only up to v21.0), so it cannot run on this image. Row: `NOT RUN: package not pinned`. Resolve itself has no benchmark.
