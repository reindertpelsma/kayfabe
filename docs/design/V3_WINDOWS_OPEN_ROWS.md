# Open Windows rows: VK-GL-CTS and DirectX-Graphics-Samples extras

Marking: **CHECKED** = read in a public upstream tree or page on 2026-11-17 (a shallow clone in a scratch directory; no code from it was run); **MEASURED** = a size or a count taken that day; **INFERRED** = reasoned, not seen; **DESIGN** = intent.

## 1. What was asked and the rules that decide the design

Owner ruling, 2026-11-17 (binding): go **open first**. An open row works for a standalone third party who trusts git only: from scratch, from the repo only, fully automatable, with no private R2 object, no account, no secret and no licence. A Worker may later use an R2 cache of a built artifact, but it is optional. Integrity pins on repo-fetched third-party sources stay.

Trust rule, 2026-11-17 (later, binding): for a third party who does not trust the repo, a sha256 of a binary pinned in git is **not** an anchor (nobody can review it). Accepted anchors are (1) an official upstream https checksum or signature fetched at run time from the upstream origin, (2) a CI-built artifact with a GitHub attestation checked by `gh attestation verify` (pinned repo, workflow, source commit), and for **sources** a pinned upstream commit or tag. Standalone runs default to trusting git only; lifting is explicit and recorded; a URL or path the user passes explicitly is always trusted (its sha256 is recorded, nothing is verified); a Worker run may use R2.

How the code follows it (all in `scripts/bench/windows/open_rows/`, all Python, PowerShell only as two thin glue files):

| Rule | Where |
|---|---|
| no binary digest in git | `open_rows.json` holds none; `kfopen_pins.validate_pins` refuses a 64-hex value or a digest/hash key in a tool entry (tests `test_a_binary_digest_in_the_tool_data_is_refused`, `..._digest_key_...`); the only 64-hex values in the file are the nuget.org certificate fingerprints |
| sources pinned by commit | `sources.cts.commit`, `sources.dxs.commit`; `kfopen_build.fetch_source` fetches that commit, runs `git rev-parse HEAD` and refuses a mismatch (`PIN_MISMATCH`) or a modified tree (`SOURCE_DIRTY`) |
| standalone = git only | `kfopen_common.Trust`: `--accept-unanchored-downloads REASON`, `--source-commit-override NAME=SHA`, `--tool NAME=PATH`, `--prebuilt DIR`; every use is written into `<root>/out/build-receipt.json` |
| user-supplied values trusted | a `--tool` path or `--prebuilt` tree is used as given; its sha256 is recorded as `trusted-by-user`, never compared |
| no cache in this PR | no object store is read or written; a prebuilt tree exists only as the user's own `--prebuilt DIR` |
| the cache plug-in point | section 7 |

## 2. The rows

Nine rows, class **`online_source`** in `gate_profiles.json` (a new class: needs an online guest to fetch and build, so it is never in `small`, `mid` or `full`; resolves as profile `open_source`; lane `discovery`). The offline gate guest cannot build: such a row is NOT_RUN (`offline-guest-without-build-tree`) unless a tree was prepared. `apps.json` is generated by `appmatrix/gen_apps.py`; the rows' `ps` body is one call of `kfopen.py run <id>` through the guest's embedded Python.

| Row id | Binary | What it does | PASS means | GPU proof (host census) |
|---|---|---|---|---|
| `vkglcts_gl46` | `glcts.exe` | 494 committed `KHR-GL46` cases (compute shader, tessellation, FBO and texture formats, SPIR-V, sparse buffers and textures, SSBO, image load/store, copy image, indirect draw, ...) in chunks of 25 | per-case result list equals the native control | any of 3D, Compute |
| `vkglcts_vk` | `deqp-vk.exe` | 375 committed `dEQP-VK` cases: ray query, ray tracing pipeline, mesh shader, sparse resources, synchronization and synchronization2, compute, api, tessellation, descriptor indexing, fragment shading rate, shader objects, device generated commands, subgroups, memory model, memory; video excluded | per-case result list equals the native control | any of 3D, Compute |
| `vkglcts_gl_dual_soak` | `kf_gldual.exe` | one process, two OpenGL 4.6 core contexts on two threads, 600 s: compute SSBO checksum, tessellation into a depth-tested FBO, blit, exact centre pixel, fence or glFinish, SwapBuffers; then the event log is searched for the Resolve crash signature | exit 0, the closed-form checks held, run lasted the asked time, no Application Error or WER naming `nvoglv64.dll` or the exe, no TDR event | any of 3D, Compute |
| `dxsamples_nbody_async` | `D3D12nBodyGravity.exe` | async compute: a compute queue simulates, the direct queue draws | window appeared, two window-only captures non-blank and different, WM_CLOSE ends the process with exit code 0 | **both** 3D and Compute (`proof_all`) |

`vkglcts_gl_dual_soak` is the group that aims at the `nvoglv64.dll` crash class of DaVinci Resolve (3 of 3, 3-4 minutes after load, in `RESOLVE_GPU_20261116.md` of the coordinator's night notes: RESEARCH, not in the repo). The hypothesis is that two contexts in one process reproduce it; **falsifier** (stated before any run): a native-Windows run of the same binary on the same die and driver crashes the same way (then it is a driver defect and not kayfabe's), or a 600 s guest run passes cleanly 3 of 3 (then this workload does not reach the crash path and the row is not the reproducer).

Two of the rows are not just survival checks. `dxsamples_reserved_resources` verifies a functional chain (key, tile mapping, upload, title) 24 times, and the two async rows need **both** engines because the existing `proof` rule is "any one holds": `proof_all` is a new, backward-compatible flag of `apps.json` and `verdict.py` (absent on every older row).

### What the pinned DirectX tree really contains (CHECKED)

Commit `68a2b1e97f71642924e74c7757ca21756ad221b5` (the same pin as `release_software.json`, a test keeps them equal), MIT. `Samples/Desktop` holds, among 26 directories, `D3D12nBodyGravity`, `D3D12ExecuteIndirect`, `D3D12ReservedResources`, `D3D12HDR`, `D3D12HeterogeneousMultiadapter`, `D3D12LinkedGpus`, `D3D12Residency`, `D3D12SmallResources`, `D3D12Multithreading`, `D3D12AsyncCommands` and, under `D3D12HelloWorld/src`, **`HelloWorkGraphs` and `WorkGraphsSandbox`**. So: work graphs exist (two console samples, each with a vcxproj, a C++ file, an HLSL file and a `packages.config`), multi-adapter exists but needs two GPUs, and there is no sampler-feedback sample (consistent with the earlier owner decision). Not in the rows, named so nobody thinks they were forgotten: `D3D12AsyncCommands` (batched async copy and clear commands, Agility SDK 620 `ID3D12GraphicsCommandList12`, INFERRED to need driver support that is not guaranteed), `D3D12Residency` (MakeResident/Evict, a candidate VA stress), `WorkGraphsSandbox` (takes an HLSL file), `D3D12SmallResources`, `D3D12Multithreading`.

Facts the harness relies on, each read in the pinned sources: windowed samples take only `-warp` as a command-line argument (never passed); `Win32Application::Run` returns the WM_QUIT wParam (0 after a normal close); `ReservedResources` starts at the least detailed mip (256x256 gives 9 mips, so mip 8), changes the mip only on UP/LEFT (more detail) and DOWN/RIGHT, calls `UpdateTileMappings` in `UpdateTileMapping`, which sets the title `Mip Level: N`, and does nothing if `TiledResourcesTier` is `NOT_SUPPORTED`; `ExecuteIndirect` toggles culling on SPACE and creates a compute queue; `nBodyGravity` creates a `D3D12_COMMAND_LIST_TYPE_COMPUTE` queue and one compute thread; `HDR` handles SPACE (full screen, avoided), Page Up/Down (swap-chain format), H and U; `HelloWorkGraphs` is a console program that prints `Device does not report support for work graphs.` and returns -1 when `WorkGraphsTier` is `NOT_SUPPORTED`. The NuGet packages are `Microsoft.Direct3D.D3D12 1.618.3`, `Microsoft.Direct3D.DXC 1.8.2505.32` and (four of the five samples) `WinPixEventRuntime 1.0.240308001`; each vcxproj imports them from `packages\` beside the project (`..\packages` for HelloWorkGraphs).

### What the pinned CTS contains (CHECKED)

Tag `vulkan-cts-1.4.7.1`, commit `0d18b347943e5e843529a05c95220e27fe30c538` (2026-10-23), Apache-2.0. `external/openglcts` (target `glcts`) and `external/vulkancts` (target `deqp-vk`) are in the same tree; `DEQP_TARGET=default` selects WGL on Windows (`targets/default/default.cmake`: `DE_OS_IS_WIN32` turns `DEQP_SUPPORT_WGL` on); the GL must-pass lists are `external/openglcts/data/gl_cts/data/mustpass/gl/khronos_mustpass/main/gl46-main.txt` (19714 cases) and `gl46-gtf-main.txt` (1742); the Vulkan lists are under `external/vulkancts/mustpass/main/vk-default/`. `glcts` registers the context factory `wgl`, and the official GL 4.6 run configuration includes a named `rgba8888d24s8` config at 64x64 (`glcKhronosMustpassGl.hpp`). `--deqp-caselist-file` reads a plain one-case-per-line file (`parseSimpleCaseList`: `#` lines skipped, a duplicate is an error). The README requires Git, Python 3, CMake 3.20 and `lxml` (the build runs `gen_framework.py`, which imports it), and tells Windows users not to build below the source tree. `external/fetch_sources.py` pins its own externals (nine git revisions and three archives with sha256) inside the commit and clones **without** `--depth`. `DEQP_DISABLE_VK_VIDEO_TESTS` exists; with `ON` the video tests are built as NotSupported and the video externals are not built, which is why the rows set it and the Vulkan list has no `dEQP-VK.video.*` case (the clips come from scripts with no checksum anchor of ours, and `vulkan_video_decode` covers video).

## 3. The caselists

`caselists/gl46_core.txt` (494) and `caselists/vk_breadth.txt` (375) are **selected**, not written by hand: `caselist_spec.json` names, per group, a must-pass file, a prefix and either `all` or N cases at evenly spaced positions (`i*len//N`, order kept). `cts_caselist.py generate --cts-tree <checkout at the pinned commit>` reproduces them byte for byte; `cts_caselist.py check` (CI, no CTS tree needed) verifies the committed files against the recorded sha256 (our own text, reviewable, not a binary pin), the pinned commit named in the header, uniqueness, name shape, the root of each list (`KHR-GL46`/`GTF-GL46`, `dEQP-VK`) and a size of 150 to 1000 cases. Selection is the only judgement: groups were chosen for the driver paths named in the ranking (compute, tessellation, FBO and texture formats, SPIR-V, multi-bind, sparse, and for Vulkan the families that the Linux row also names).

"GL multi-context" is **not** a CTS group in `gl46-main.txt` (CHECKED by grep: no case is about contexts or threads beyond viewport and stream names), so the multi-context coverage is the soak, not the caselist.

## 5. How a row runs

```
python scripts\bench\windows\open_rows\kfopen.py run vkglcts_gl46 [--root C:\kfopen] [--control FILE] [--role guest|native]
```

`run` is `preflight` (a named NOT_RUN reason, or none), `prepare` (toolchain, pinned source, build; idempotent, keyed by a recipe hash of the commit and the build recipe), then the row. Everything it does is in `<root>`: `tools/`, `src/`, `build/` (outside `src/`), `downloads/`, `out/build-receipt.json`, `results/<row>/`. `prepare` can be run alone ahead of the apps so that the build does not count against a row timeout (the matrix rows carry 7200 s to 14400 s timeouts because they build on first use).

Exit codes and lines: 0 PASS (`KFOPEN VERDICT PASS row=<id> ...`), 1 FAIL (`CHECK <name> FAIL <why>`, the matrix `fail_rx`), 3 NOT_RUN (`KFNOTRUN <id> reason=<token> (<detail>)`, which `verdict.py` now maps to NOTRUN), 2 usage or refusal. Every row's `rx` was tested against the text the code really prints (`test_open_matrix.RxMatchesWhatTheHarnessPrints`), and no row can pass by printing the NOT_RUN line.

**CTS rows.** `cts_run.run_cases` feeds the binary chunks. A chunk whose process died leaves one case that began and never ended; it is booked as `Crash` (or `Timeout` when the chunk timed out), the rest goes back to the queue, a fresh process continues. A lost qpa log falls back on stdout. Every case ends with exactly one status. Results go to `<row>.<role>.tsv` (`case<TAB>status`, header with commit, caselist sha256, GPU name and driver, never a UUID) and fail details to `<row>.<role>.details.tsv`, UUID-scrubbed (`scrub_uuids` maps any UUID to the fake prefix `fa4efa4e-fa4e-4fa4-8fa4-fa4efa4e....` and keeps equalities).

**Native control and PASS.** The control is the same binary built from the same pinned commit on **native Windows on the same die** (the windows-on-vast reference path, `V3_WINDOWS_ON_VAST.md`; the owner note records it as the native-parity reference, public, online, ISC), run with `--role native`. `check_control` refuses a control from another commit, another caselist, another binary or another GPU model. `diff_results` compares status for status: PASS needs equal case sets and equal statuses; a missing case on either side is INCOMPLETE (NOT_RUN, no verdict); otherwise FAIL. Classes (`cts_results.classify`): `GUEST_REGRESSION` (native Pass-like, guest Fail/Crash/Timeout/DeviceLost/...) and `GUEST_LOSES_FEATURE` (native Pass-like, guest NotSupported) are the **candidate kayfabe bugs** and are printed (`KFOPEN CANDIDATE`); `NATIVE_ONLY_FAIL`, `GUEST_GAINS_FEATURE`, `DIFFERENT_FAILURE` and `QUALITY_DIFF` also make the lists unequal and are reported separately. A differing case is rerun alone once; a rerun that equals the control is a flake, adopted and listed (`FLAKY_RESOLVED`). Without a control the row is NOT_RUN (`no-native-control`) and keeps its results: the **discovery lane comes first**, then the native run, then the diff (`kfopen.py diff --native N --guest G`, exit 0/1/3).

**Sample rows.** `dxs_harness.run_window_sample` starts the exe, waits up to 90 s for a visible top-level window of that process, posts the keys with `PostMessage(WM_KEYDOWN/WM_KEYUP)` (the samples read them in their `WndProc`, no focus needed), takes two **window-only** captures (`PrintWindow(PW_RENDERFULLCONTENT)` of that one HWND; there is no desktop capture and the rows set no host screenshot), posts `WM_CLOSE`, waits 20 s and records the exit code. `analyze_pixels` hashes the full capture (sha256 recorded) and judges blankness on about 4096 sampled pixels. Animated samples must show two different captures. `judge_window` returns named checks; GPU use itself is not asserted by the harness: the matrix supervisor samples the process tree's GPU Engine counters and `verdict.py` applies `proof` or `proof_all`.

## 7. Where a cache plugs in later (not in this PR)

A Worker may keep an R2 copy of a built tree (`build/cts`, the sample `bin/x64/Release` directories). Per the owner rule that cache may only be trusted if a CI workflow built it with a GitHub attestation: the plug-in point is `kfopen.prepare`, where an attested artifact would take the place of `build_cts`/`build_dxs` after `gh attestation verify` of pinned repo, workflow and source commit; the recipe hash of `kfopen_build.recipe_hash` is the cache key. Until that workflow exists the only cache is the user's own `--prebuilt DIR`, trusted and hash-recorded. The default stays "build from the pinned upstream source".

**What could go wrong (each a hypothesis with its falsifier: the first run).**

1. *The VS 2026 channel replaces 2022.* `aka.ms/vs/17/release` is the 2022 channel, so the pinned bootstrapper gives 2022; falsifier: `vswhere` reports another major version. Risk: `PlatformToolset=v143` breaks on a new drift of the SDK.
2. *`glcts`/`deqp-vk` do not link or their data is not copied* (`add_data_dir` post-build copy; the README warns about build directories under the sources). Falsifier: `locate()` finds no exe, or the first chunk reports every case `InternalError`.
3. *`--deqp-gl-config-name=rgba8888d24s8` finds no WGL pixel format* on the guest (a virtual display or the driver may offer other formats). Falsifier: every GL case `NotSupported` or `InternalError` natively too, which is then a discovery fact, not a kayfabe bug.
4. *Window-only capture of a flip-model D3D12 swap chain is black* with `PrintWindow`; falsifier: `screenshot_nonblank` fails on the **native** control run as well. Fallback (not implemented): crop the window rectangle from the desktop duplication.
