Goal (owner, night plan item B): boot the automated-test Windows 11 LTSC baseline (guest driver 580.88) under kf3 on vast

## 2. Procedure (per die)

1. Rent (`vms_enabled=true`, KVM image, `--disk 150`), `/root/night/arm_autodestroy.sh <id> 240`, check `df -h /`, `/dev/kvm`, the GPU.
2. `box_facts.sh` (before the driver swap and after): PCI ids, BAR region sizes, Resizable-BAR capability, link, host BAR1 total.
3. `provision_full.sh` with D2/D3; READY line; `v3_gates.sh` (bare-metal gates on the same box: if these fail, the box is at fault).
4. Image (D4) to `/root/win`; `die_run.sh phase1`, then `die_run.sh phase2`; logs, kf3 `qemu.log` (filtered), screenshots back to git.

## 4. Traps found on the way

- **`provision_box.sh`'s mirror floor rejects a fast box.** It times a download of `dists/jammy/Release` (~130 KB) and refuses
  below 200 kB/s; on vast 55835556 (Nevada) all three mirrors measured 120–165 kB/s that way while a 20 MB ranged download of
  the same mirrors ran at ~5 MB/s [measured]. The small file measures latency, not bandwidth. Worked around on the box copy
  (floor 50 kB/s); the script itself is not changed tonight.
- **The first ssh of a vast VM reaches a different host key** (the pre-boot endpoint), so a strict known_hosts refuses the VM
  once it is up; drop the entry.
