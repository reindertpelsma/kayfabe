# Custom hosts: Worker, daemon and seeder contract

**STATUS: DESIGN-ONLY 2026-11-12** (coordinator, from owner decisions; sources: memory project_platform_testing_worker_20261103, RELEASE_SEQUENCE.md "CUSTOM HOSTS", "Seeder address rule", box protocol 7 in ci/vast-broker/docs/BOX_PROTOCOL.md). Shared contract for three work packages: W1 Worker (Durable Object + admin), W2 daemon (scripts/kfhost), W3 seeder (nginx template + probe + helper). Nothing here is deployed.

## Principles (owner decisions)
- Custom hosts are enrolled boxes that are NOT rented from Vast. The daemon NEVER runs on Vast boxes (Vast keeps API + per-run token).
- Transport: outbound WebSocket from the daemon to a Durable Object (one DO per box, hibernation API). Auth: Cloudflare Access service token (anti-bot gate only) + a per-box token (distinct from run tokens). The socket carries liveness, capabilities, job offers and (owned boxes only) remote commands. Logs/progress/results/evidence travel over the EXISTING HTTPS box protocol (POST /report/<run>, /run-report, /evidence, /blob-url ...) with the per-run token carried in the offer.
- Profiles are assigned SERVER-SIDE by the admin, never self-declared by the box:
  `owned` (full access, driver swaps, remote commands allowed), `container` (container with /dev/kvm + /dev/nvidia*, host driver fixed, no remote commands), `borrowed` (distrusts us: declarative assignments only; the daemon fetches the commit from the PUBLIC repo, verifies commit SHA and tree key, runs standalone/manual mode: no system changes, official URLs only, no private CF assets, no remote shell).
- Results from custom hosts are unattested tripwires like all others; they may satisfy requirements only when the admin enabled the box for that tier ("reproduced" tier = rented/controlled/enrolled; community results never count).
- Selection: custom hosts that match the requirements and are enabled are preferred over Vast; one run per box at a time; availability window / `opportunistic` flag.
- A box NEVER supplies an address the Worker contacts. Seeder addresses come from the Vast API (Vast boxes) or from admin configuration (custom boxes: remote IP, external TCP port, inner TCP port; the IP is prefilled from the connect address but editable).

## WebSocket messages (JSON, one object per frame, `v: 1`)
daemon -> DO:
- `hello {v, box_id, version, capabilities}` first frame after upgrade. capabilities = {gpu_name, compute_cap, vram_gb, driver, module_flavor: open|proprietary, kvm: bool, cpu_model, cores, ram_gb, disk_free_gb, download_mbps (measured, optional), display: bool, can_swap_driver: bool, container: bool, os, kernel}. The DO stores them; the admin profile decides what they are allowed to do.
- `heartbeat {ts, state: idle|busy, run_id?}` every 15 s.
- `ack {offer_id}` / `nack {offer_id, reason}`.
- `seed_register {offer_id, artifact: {name, sha256, size}, path}`; the DO answers after probing (below).
- `cmd_output {cmd_id, seq, stream: stdout|stderr, data, eof?}` and `cmd_done {cmd_id, rc}` (owned boxes only).
DO -> daemon:
- `welcome {v, box_id, profile, heartbeat_s}` (profile is informative; the daemon enforces the strictest of profile and local config).
- `offer {offer_id, request_id, run_id, run_token, assignment: {repo, commit, tree_key, stages?, requirements?, env?}, deadline_ms}`; `borrowed` offers contain ONLY repo/commit/tree_key/stage names from a fixed allowlist, never scripts or commands.
- `cancel {offer_id}`.
- `seed_ack {ok, reason?}`.
- `cmd {cmd_id, argv|shell}` (owned only; refused by the daemon on other profiles).
- `ping`/close codes: 4401 bad token, 4403 box disabled, 4409 replaced by a newer connection.

## Seeder probe (W3 + W1)
- Admin config per box: `seeder: {enabled, remote_ip, external_port, inner_port}`. For Vast instances the Worker uses the IP + mapped port that the Vast API reports for the instance.
- Registration probe: the Worker fetches `http://<hostname>:<port>/<token>/probe.txt` (hostname = an IP-encoding mapper name of the configured IP, see the MEASURED note below; never the raw IP) (a small dummy file served by the box's nginx under the same token path as the artifact) and compares its fixed content; success => `seed_ack {ok: true}` and the box may be a seeder for the session; failure => `ok: false` and the box is treated as unable to open a port. Timeouts <= 5 s per name, one attempt per name, no redirects, only http to the configured address, never an address from the box.
- Consumers receive the artifact record from the Worker: `url` (`http://ip:port/<token>/<name>`), `fallback_url` (the hostname form of the first mapper that passed the probe, so a name known to work from Cloudflare's side; the sslip.io form if the probe did not apply; for `kf_fetch.py --fallback-url`, because boxes behind http proxies, DNS proxies or NAT64 may only reach the hostname), `sha256` and `size`; all four are Worker-published and never taken from the seeder's responses; they verify the hash and fall back to a local build at the deadline.
- [MEASURED 2026-11-12, coordinator] A Worker `fetch()` of a RAW IP (`http://92.67.98.9:25493/...`) returns 403 `error code: 1003` in under 2 ms: Cloudflare blocks direct IP access. A HOSTNAME that resolves to the IP works on a non-standard port: `http://92-67-98-9.sslip.io:25493/<token>/probe.txt` answered 200 with the exact body in about 100 ms; `92.67.98.9.nip.io` also works (about 900 ms); a wrong token answers 404; a closed port answers Cloudflare 522 after about 19 s. Therefore the probe host is always a hostname from an IP-encoding DNS mapper. [MEASURED 2026-11-12 with dig, coordinator] sslip.io and nip.io share the same nameservers (one operator), so nip.io is no independent second path and is not used; `a-b-c-d.traefik.me` (Traefik Labs, its own nameservers) resolves correctly via 1.1.1.1 and 8.8.8.8; local-ip.sh also works (listed, disabled); cloud-ip.cc is not an IP-encoding mapper and xip.io is dead. [NOT YET MEASURED] traefik.me through a real Worker fetch (the coordinator measures it in integration). The probe tries `<a-b-c-d>.sslip.io`, then `<a-b-c-d>.traefik.me` (the `MAPPERS` constant in `hosts.js`; a third name is a one-line change): one attempt per name, each hard-bounded at 5 s, and the first name that returns the exact probe text wins; if both fail the box is "cannot open a port" for the session. There is no admin-chosen or own-zone name (owner ruling 2026-11-12: the http connection is untrusted anyway; the Worker publishes url, sha256 and size, and consumers stage to `.unverified` and discard on a size or hash violation). The IP must be a public dotted-quad (no IPv6 for now; no private, loopback, link-local or CGNAT range). The probe function takes its fetcher as an argument.

## Admin API (extends the existing owner admin auth; JSON)
`GET /admin/hosts`, `PUT /admin/hosts/<box_id>` {enabled, profile, tiers: [small|middle|large], seeder, window?, opportunistic?, notes}, `POST /admin/hosts/<box_id>/token` (mint/rotate the per-box token; the token is shown once, stored hashed), `DELETE /admin/hosts/<box_id>`, `POST /admin/hosts/<box_id>/cmd` (owned only; command log kept in the DO, bounded).

## Selection (planner)
`hostsFor(requirements)`: enabled boxes, connected (heartbeat < 45 s), idle, profile allows the tier, capabilities satisfy the requirement (die/family, driver needs vs can_swap_driver, kvm, display), inside the availability window; ordered: non-Vast first, then lowest-cost Vast fallback (existing logic).

## Boundaries
- No secrets in repo; tokens only in env/DO storage hashed; the daemon holds a per-box token + Access service token in a 0600 file it reads at start.
- Python rule: logic in Python (shell is glue only); the daemon runs in a venv created by an explicit setup command; deps: `websockets` pinned with hashes.
- GPU-free tests everywhere: fake WS server for the daemon, workerd/miniflare for the DO, local HTTP server for the probe.

## Trust model (owner ruling 2026-11-12)
All hosts used for a CI GPU test are untrusted by design: none can affect the release artifact and none can reach private R2. So every Vast box and every enrolled box trusts every other for artifacts (a seeder's sha256 and size are labelled `source=seeder_reported`, integrity of the transfer only; where the Worker knows an artifact independently, a registration must match it and is labelled `worker_pinned`). The one exception is a `borrowed` host (distrusts us): it never consumes an artifact from another box and builds from public sources only; it may still seed to others. Profiles are `owned | container | standard | borrowed`; `standard` (an enrolled throwaway box rented elsewhere, treated like a Vast box) is the default for a new box. The `borrowed` mode is PARKED pending an owner decision: its code lives in one section of `hosts.js` (`BORROWED`) plus the `isBorrowed`, `BORROWED_ASSIGNMENT_KEYS` and `seedAllowed` uses, so it can move to a follow-up branch in one step. The flags model (daemon-enforced flags in hello, locked admin fields) is NOT built.

| consumer profile | receives artifacts from other boxes |
|---|---|
| owned, container, standard | yes, from any seeder |
| borrowed | never |

## Wire values (one golden fixture: `ci/vast-broker/test/fixtures/hosts-wire.json`; the daemon copies it)
- Frames: JSON objects with `type`; `v` is optional and must be `1`. The Worker validates every daemon frame (`validateDaemonFrame`); an invalid frame of a known type before hello closes the socket 1008, after hello it is answered with an `error` frame (`BAD_FRAME`); a flood (more than about 10 frames a second sustained, bursts of 20) closes 1008; a frame over 64 KiB closes 1009.
- `repo` = `https://github.com/reindertpelsma/kayfabe` for every profile (the allowlist is the one constant `REPO_ALLOWLIST`; the Worker var `HOST_REPO_ALLOWLIST`, a JSON array of https URLs, replaces it). `commit` = `^[0-9a-f]{40}$`. `tree_key` = lowercase hex SHA-256, `^[0-9a-f]{64}$`. `stages` = `provision, cuda_host, merge_bar, cuda_guest, apps, windows_gate, windows_apps, specviewperf, ladder` (`WIRE_STAGES`). `deadline_ms` = epoch milliseconds, an integer.
- `compute_cap` = a string such as `"8.9"`; `pci_device_id` = four lowercase hex digits; `gpu_name` as printed by the driver. The `die` is never a box claim: the Worker derives it from `gpu_name` and `compute_cap` through the existing die tables (`dieRules` in `defaults.json`, via `gpuClass`); a box without a derived die never satisfies a die requirement (fail closed). The PCI device id is recorded for the admin; no PCI table exists in the Worker yet.
- Seed: token = exactly 8 characters `[a-z0-9]`; `path` = `/<token>/<artifact name>`; the probe file is `/<token>/probe.txt` with the exact content `kfseed-probe-v1\n`.
- Upgrade: `GET /hosts/<box_id>/ws` (behind the broker path prefix, if one is set) with `Authorization: Bearer kfh_...`. The gateway answers 401 over plain HTTP, before any Durable Object is woken, for a missing or malformed token or a missing Upgrade header, and 429 beyond 30 upgrades a minute per address; it cannot check that the box exists (only the box's Durable Object knows). Close codes: 4401 bad token (also unknown box and no token minted), 4403 disabled, 4408 no frame for 45 s, 4409 a live connection already exists (the NEW connection is refused; only a silent socket is replaced).
- Token rotation closes every open socket of the box with 4401 immediately; a socket that was mid-upgrade is also dropped (the check and the accept are atomic, and each frame re-checks the token generation).

## Implementation notes (W1, Worker side; code in `ci/vast-broker/src/hosts.js` and `hostbox.js`)
- Admin (owner Access identity, in `ci/vast-admin`): `GET /api/hosts`, `GET|PUT|DELETE /api/hosts/<box_id>`, `POST /api/hosts/<box_id>/token`, `POST .../cmd`, `PUT .../commands-until`, `POST .../enrol`; each is forwarded to the DO as `/admin/hosts...` on the internal origin. A reserved DO instance `__index__` lists the box ids (at most 64). The list shows `idle_since` (from the heartbeat) and the config.
- Config per box: `enabled`, `profile`, `tiers`, `seeder {enabled, remote_ip, external_port, inner_port}`, `window {start, end}` in UTC, `opportunistic`, `hourly_price_usd` (0 to 50, orders selection only), `notes`. `commands_until` is not part of the config PUT: it is set only through `PUT .../commands-until` (`{commands_until: <epoch ms>|null}`, at most 4 h from now, owned boxes only, default none), survives a config edit and is dropped by a profile change. `cmd` frames need profile `owned` AND an open window; unset or expired answers `CMD_DISABLED`.
- Enrol: `POST .../enrol` rotates the token (closing old sockets) and returns once `{box_id, shown_once, command}`: a one-line command that writes the token with `printf` (a shell builtin, never an argv value) to `kfhost.token`, downloads `scripts/kfhost/bootstrap.py` of the commit pinned by the Worker var `HOST_DAEMON_COMMIT` (40 hex, no default: the route answers 503 `ENROL_UNAVAILABLE` while it is unset) and runs it with `--worker-url <WORKER_URL>[/<path prefix>] --box-id <id> --commit <sha> --token-file kfhost.token`. The flag names are the Worker's proposal for W2's bootstrap script. The response is no-store and the token is never stored in clear or logged.
- Offers (internal origin, called by the planner): body `{request_id, run, tier, assignment, deadline_ms, artifacts?}`. The tier must be enabled for the box (`TIER_NOT_ENABLED`). `borrowed` assignments contain only repo, commit, tree key and stages; the others may add bounded `requirements` and `KF_*` `env`. The run token carries `box` and `hp` (box id and profile) claims; the offer record keeps box, profile, tier, nonce and a generation. `customHostResultCountable(claims, config, tier)` is the check ingestion must apply (it is not wired: no custom-host result is recorded by the Worker yet). An offer is idempotent by `request_id` (redelivery with the same `offer_id` and a fresh token); an ack after the ack timeout still counts until the deadline; once acked the same request answers `duplicate`.
- Seeds: the probe runs at most once per offer (its result is cached on the offer); a seed registration whose offer was replaced while the probe ran (a new generation) writes nothing (`STALE_OFFER`); `GET /internal/seed?consumer=<profile>` returns the record unless the consumer is `borrowed`.
- Storage: heartbeats keep liveness in the socket attachment and write storage on a state change or once a minute; command output is buffered and flushed in batches (4 KiB or 1 s, on done, on read), capped at 32 KiB per command, and ignored after done. A buffered tail may be lost if the object is evicted between flushes.
- Git-only boxes (PARKED with the borrowed section of `hosts.js`): `commitEligible(snap, run)` lets a git-only box (profile `borrowed`, or a snapshot with `enforced.trust_git_only`) receive only a run whose verified OIDC claims show `event_name` `push` on `refs/heads/master` or `refs/heads/next`; anything else, and a run without claims, is skipped with the recorded reason `COMMIT_NOT_IN_MAIN_HISTORY` (`explainHosts` returns the reasons for debug output). No GitHub call is made. `requirements.run = {event_name, ref}` is supplied by the planner from the claims admission already verified. Other boxes have no commit restriction.
- Run report: the report normaliser keeps a boolean `tree_key_mismatch` (the daemon's warning on a non-git-only profile, omitted when the tree keys are equal), publishes it in the report document and drops any other type; it never affects the verdict. The golden fixture has an example under `run_report_fields`.
- Selection: `hostsFor(requirements, snapshots, now)` is pure and orders non-opportunistic first, then the cheaper hourly price (unknown after known), then box id; `hostSnapshots(env)` and `offerToHost(env, boxId, offer)` are the planner's seams. An empty result means "fall back to Vast". The planner itself is not changed.
- Not deployed. Adding the Durable Object class needs the `v2` migration in `wrangler.toml`; the bundle hash pin (`deployment.json`, `DEPLOYED_BUNDLE_SHA256`) must be regenerated by the coordinator.

## Interoperation with the daemon (round-2 review, 2026-11-12)
The golden fixture `ci/vast-broker/test/fixtures/hosts-wire.json` is the single source of truth for every frame (copy it byte for byte); `ci/vast-broker/test/hosts-wire.test.js` validates ALL of its valid and invalid examples against the Worker's validators.
- **hello** may carry `enforced` (an object of at most 8 booleans, e.g. `distrust_us`, `allow_cmd`, `container`); it is stored read-only per box and shown in the admin view (the admin config has no way to change it). **heartbeat** may carry `idle_since` (a number, epoch ms; accepted, the Worker keeps its own idle time).
- **Offer**: `{type, v, offer_id, request_id, run_id, run_token, run: {nonce, runner_nonce, sha}, assignment, deadline_ms}`. `deadline_ms` stays milliseconds. `run.nonce` (32 hex) and `run.runner_nonce` (64 hex) are supplied by the planner from the admission of the run (`/internal/offer` body `run.nonce`, `run.runner_nonce`); `run.sha` is the commit. The daemon returns all three in its result. The Worker does not store the runner nonce or the run token.
- **Result**: the daemon reports through the existing result route (`POST /report/<run>-<attempt>`, the per-run token from the offer) with EXACTLY the keys `hardware, nonce, runner_nonce, sha, suites, verdict` (plus the optional `host_reference`, `host_claims`, `matrix_receipts`). `hardware` is required and has exactly `{gpu_name, compute_cap, driver_version}` as the Vast payload reports it: `gpu_name` matches `^[A-Za-z0-9_. -]{1,100}$` (the driver's name with spaces or underscores, e.g. `RTX_4070`), `compute_cap` is an integer (compute capability times 100, `890` for 8.9; not the string of the hello capabilities) and `driver_version` is the NVIDIA host driver version (`580.159.04`). `tree_key_mismatch` must NOT be in the result (the result route refuses unknown keys with `BAD_REPORT`): the daemon sends it in the run report (`POST /run-report/<run>-<attempt>`), where it is kept when boolean.
- **ack / ready / nack**: `ack` = the offer is accepted (profile checks passed, before the fetch); `ready` = the commit is fetched and verified (`{type: 'ready', offer_id}`, only after an ack); `nack` = refused, or, after an ack, failed: the offer becomes `failed` with the reason and `unmet: true`, the box is released and the requirement stays unmet (UNATTRIBUTED); a failure is never recorded as a result.
- **welcome** carries `commands_until_ms` (epoch ms or null) and `cmd_output_per_s` (20: the pacing the daemon must keep for `cmd_output`; the bucket is 40 burst, 20 per second, separate from the 20 burst, 10 per second of every other frame; a coarse 80 burst, 40 per second bucket sits in front of the parse). **cmd** frames carry `commands_until_ms` so the daemon can verify freshness.
- **seed_register** may carry `warnings` (at most 5 printable-ASCII strings of at most 200 characters); they are stored with the seed record and shown in the admin view. Concurrent registrations of an offer share the one probe in flight; another token meanwhile is `PROBE_USED`.
- **Consumers**: the planner passes `seed_from: <seeder box id>` in `/internal/offer`; the Worker reads the seeder's record (refused for a `borrowed` consumer: 403 `SEED_NOT_ALLOWED`; none: 409 `SEED_UNAVAILABLE`) and puts `assignment.seed = {url, fallback_url, sha256, size, name}` into the offer. A planner can never supply `assignment.seed` itself.
- **Shared rules**: box id `^[a-z0-9][a-z0-9-]{0,39}$` on both sides; artifact name `[A-Za-z0-9._-]{1,100}` without `..` and without a leading `-` or `.`; artifact size at least 1. The public-IP check also refuses TEST-NET-1/2/3, `192.88.99.0/24` and `240.0.0.0/4`.
- **Upgrade answers that are not 101**: the gateway answers 401 (missing or malformed token, or no Upgrade header), 404 (unknown route, bad id), 429 (more than 30 upgrades a minute from one address). Cloudflare Access in front may answer 302 or 403 for a missing or wrong Access token. The daemon must treat every non-101 answer (3xx, 401, 403, 404, 429, 5xx) as "retry slowly" and must not read a 3xx as a WebSocket close code.
- **Eviction**: command output is buffered; the first buffered frame of a burst writes a durable `dirty_since` marker and sets an alarm that flushes within one second. If the Durable Object is rebuilt while the marker is set, the log is flagged `incomplete: true` when it is completed, instead of claiming a complete run (the workerd test simulates the eviction by clearing the in-memory state, not by restarting workerd).
- **Enrol command** (`POST .../enrol`): two lines. A comment line tells the admin to write the Access client SECRET into `./accessfile` (the Worker never knows or prints it), then `umask 077 && printf '%s' '<token>' > kfhost.token && curl -fsSL <raw github url of the pinned commit>/scripts/kfhost/bootstrap.py -o kfhost-bootstrap.py && python3 kfhost-bootstrap.py --repo <first allowlist entry> --commit <HOST_DAEMON_COMMIT> --worker-url <WORKER_URL[/prefix]> --box-id <id> --token-file kfhost.token --access-id <HOST_ACCESS_ID or the placeholder <ACCESS_ID>> --access-secret-file accessfile`. `HOST_ACCESS_ID` is an optional public Worker var (the Access client id; not a secret). The flag set matches `bootstrap.py` of PR #346 (required `--repo --commit --worker-url --box-id --token-file`; optional `--access-id --access-secret-file --work-dir --dry-run`); the test checks the command against that literal list because the daemon's branch is not importable from this one (I also ran the real `bootstrap.py` argparse once against a generated command, see the PR description).
